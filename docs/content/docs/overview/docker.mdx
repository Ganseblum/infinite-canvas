# Docker 部署

本 Fork 的账号后端版本使用 Docker Compose 同时部署 Vite 静态前端、Go API 和 MySQL，自建当前源码的 app / api 镜像。不要用上游发布镜像代替这一版本，也不要直接执行未配置 env 的 `docker compose up -d`。

三个服务的职责与数据落点：

- `app`：Vite 构建的静态站点由容器内 nginx 托管，并把 `/api` 反代到 api 容器；它只是静态文件加反代，不保存任何业务数据。
- `api`：Go 后端，负责账号、画布、素材、生成记录、AI 转发、支付回调与管理接口；画布、素材与生成记录全部写入 MySQL，图片、视频等媒体文件写入 `data/media` 绑挂载（或私有 S3 桶），MySQL 数据落在 `data/mysql`。两个目录都在部署目录下的 `./data`，升级前直接打包即可备份。
- `db`：MySQL 8.4，仅 compose 内网可达；测试环境由 `deploy/compose.test.yml` 额外映射 `127.0.0.1:13306`，正式环境不映射宿主机端口。

## 先部署测试环境

从你的 Fork 获取指定测试提交，分别准备测试、正式代码目录。测试目录执行：

```bash
cp deploy/env.test.example deploy/env.test
# 填写真实数据库凭据、随机密钥、管理员与 APP_BASE_URL
./deploy.sh test build
./deploy.sh test up -d
```

测试前端只绑定宿主机 `127.0.0.1:3100`。宿主机 Nginx 配置测试域名和 HTTPS，反代到该端口；容器内 Nginx 把 `/api` 原样转发到 Go。两层代理都需满足 SSE 与媒体上传需求。

测试 MySQL 只映射服务器回环 `13306`，本地通过 SSH 隧道连接。DBeaver 用于查看同一个测试库，电脑不必安装 MySQL。连接步骤见[本地开发](/docs/development/local-development)。

## 正式环境

测试通过、用户同意合入 `main` 后，正式目录检出已验收 tag，填写独立 `deploy/env.prod`，完成备份恢复准备，再执行：

```bash
./deploy.sh prod build
./deploy.sh prod up -d
```

正式前端绑定 `127.0.0.1:3200`，由宿主机域名反代提供 HTTPS；正式数据库不映射宿主机端口。正式关闭测试 seed，使用独立数据库、密钥和媒体存储。正式镜像标签包含版本号并保留旧镜像，升级前备份；当前自动改表不能只靠切旧镜像回滚。

## 数据与本地开发

只保留测试、正式两套库。本地前端可以经 SSH 代理服务器测试 API；本地 Go 与测试 Go 共用测试库的完整模式，还需共享测试媒体桶和启动维护/后台任务执行开关，当前待实施。

账号、画布、素材记录与生成记录由 Go / MySQL 保存；图片、视频等文件存在媒体卷或私有 S3 桶。联合备份包含数据库、媒体、env/密钥和版本记录。平台 AI 渠道密钥加密存库，不是浏览器直连渠道方案。

完整部署顺序、DBeaver、共享数据前置条件与验收清单见仓库 `deploy/README.md`；真实服务器信息见《我的规划/部署方案（测试与正式环境）.md》。服务器部署与 Docker 静态资源仍需实际验收。

## 文档站与统计

文档站位于 `docs/`，是独立 Next.js standalone 应用，不打入主应用镜像：

```bash
cd docs
docker compose up -d
```

主应用统计默认关闭；可在 app 的环境变量中设置 `ANALYTICS_GA4_ID`、`ANALYTICS_BAIDU_ID`。配置由容器启动时写入 `config.js`，只在自己的站点使用，不提交真实统计 ID。
