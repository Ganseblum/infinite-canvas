# 画布数据结构

本文档说明画布数据的权威存储位置与结构。资源化改造完成后，画布、素材、生成记录与媒体全部以服务端为权威，浏览器只保留界面状态、Agent 会话与提示词缓存。

## 当前存储位置

服务端（权威）：

- 画布项目、素材、生成记录：MySQL，通过 `/api/canvases`、`/api/assets`、`/api/generations` 读写。
- 媒体文件（图片、视频、音频等）：`STORAGE_DRIVER=local` 时落 api 的 `MEDIA_ROOT`（compose 部署为 `data/media` 绑挂载），`s3` 时走私有对象存储；展示一律经 `/api/media/{storageKey}`。
- 画布导出与导入：导出 JSON 时按 `storageKey` 从 `/api/media` 逐个下载媒体，导入时先上传媒体再建画布/素材。

浏览器本地（仅非权威状态，清空不丢业务数据）：

- 界面与配置状态：`localForage` 数据库 `infinite-canvas` 的 `app_state` store，按 key 保存主题、语言、配置偏好、插件列表、提示词来源开关等（key 形如 `infinite-canvas:theme_store`）。
- Agent 会话：画布 Agent 的对话消息与本地缩略图引用，随会话独立保存，不写入画布项目数据。
- 提示词缓存：`localForage` 数据库 `infinite-canvas` 的 `prompt_cache` store，缓存第三方提示词来源最近一次成功拉取的内容。

浏览器不再保存画布、素材、生成记录或媒体二进制；旧版本 localForage 的 `image_files` / `media_files` 已废弃，升级前的旧数据不会自动上传，需要保留时先用旧版本导出、再在新版本导入。

## 画布 data 字段结构

画布内容整体作为 `data` 字段由服务端保存（单画布上限 2 MB）；画布的 `id`、`title`、`revision` 等由服务端记录管理，不在 `data` 里。

```ts
type CanvasData = {
  nodes: CanvasNodeData[];
  connections: CanvasConnection[];
  chatSessions: CanvasAssistantSession[];
  activeChatId: string | null;
  backgroundMode: "lines" | "dots" | "blank";
  showImageInfo: boolean;
  viewport: { x: number; y: number; k: number };
};
```

字段说明：

- `nodes`：画布节点列表。
- `connections`：节点连线列表，只保存节点 ID，不保存端口坐标，渲染时按节点位置与尺寸计算路径。
- `chatSessions` / `activeChatId`：画布内助手会话。
- `backgroundMode`：画布背景模式。
- `showImageInfo`：是否显示图片信息。
- `viewport`：视口变换，`x/y` 是屏幕平移，`k` 是缩放比例。

## 节点结构

每个节点是一个 `CanvasNodeData`：

```ts
type CanvasNodeData = {
  id: string;
  type: CanvasNodeTypeId;
  title: string;
  position: { x: number; y: number };
  width: number;
  height: number;
  metadata?: CanvasNodeMetadata;
};
```

- `type`：内置六类（`image` / `text` / `config` / `video` / `audio` / `group`），插件节点为 `"<pluginId>:<name>"` 形式的开放字符串。
- `position` / `width` / `height`：画布世界坐标，不是屏幕坐标。
- `metadata`：节点内容和业务状态，按节点类型不同，常见字段包括 `content`、`prompt`、`status`、`fontSize`、`generationMode`、`model`、`size`、`count`、`naturalWidth/naturalHeight`、`freeResize`、`images`（多图槽位）、`primaryImageId`、`inputOrder`、`storageKey`、`mimeType`、`bytes`、`videoTaskId` 等。
- 图片与视频节点保存展示 URL 和 `storageKey`，真实媒体由服务端按 `storageKey` 提供；删除节点、画布或素材时，服务端按引用清理其独占媒体。

## 助手会话结构

助手会话保存在画布 `data` 内：

```ts
type CanvasAssistantSession = {
  id: string;
  title: string;
  messages: CanvasAssistantMessage[];
  createdAt: string;
  updatedAt: string;
};
```

画布 Agent（Codex）的会话不在此结构里：Agent 消息按 `threadId` / `turnId` / `itemId` 归属，随 Agent 本地存储独立保存，历史快照成为权威后不与实时事件重复合并。
