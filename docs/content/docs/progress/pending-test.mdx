## Credits, payment, and admin console (phase 3)

- Ledger: adjusting the `granted` bucket in the admin console increases only `grantedMicros`, writes a transaction with the right bucket, amount, and balance-after, and leaves the plan at `free`; `SUM(amount_micros)` grouped by bucket always equals the two buckets; deducting a bucket below zero is rejected without touching balances or transactions; no transaction write endpoint exists.
- Plans and quota: a user holding only granted credits stays `free`; after a top-up `/api/me` reports `paid` with larger storage, per-file, and retention limits without any admin action; exhausting purchased credits inside the entitlement window keeps `paid`, then `sunset` for 60 days, then `free`; when usage exceeds the derived plan limit `readOnly` is true and uploads return 403 `READ_ONLY` (with `planId`), while browsing, editing, deleting, and exporting still work; an upload that would exceed the plan returns 507 `STORAGE_QUOTA_EXCEEDED` with `used` and `limit`; concurrent uploads keep `usage.storageBytes` equal to `SUM(media_files.bytes)`.
- Orders and callbacks: order snapshots keep price, both buckets, and entitlement days after the package changes; the same `provider_order_id` callback credits only once and returns the channel-specific success response again; a forged signature returns 400 `INVALID_SIGNATURE`; a mismatched amount is rejected and logged; cancelling a paid order returns 409 `ORDER_ALREADY_PAID` and another user's order id returns 404; a pending order past 30 minutes is queried upstream first and only then marked failed; topping up twice extends `paid_until` from the previous expiry without shortening it.
- Model catalog and promotions: a new model appears in the models page immediately with controls rendered from its `constraints`; removing `quality` removes the quality selector; switching models falls back to a valid option; the price table shows every combination and the charge updates per combination; saving rejects missing, duplicate, negative, or out-of-constraint prices; discounts resolve by specificity then priority without stacking; conflicting rules return 409 `PROMOTION_CONFLICT`; disabling or editing a promotion bumps its version and `nextPricingChangeAt` refreshes the price matrix without a manual reload; deleting a model that has transactions is rejected (disable instead), and packages have no delete action.
- Cleanup and deletion: deleting a canvas and running the user's cleanup removes only its exclusive media and lowers usage; a soft-deleted canvas keeps its media; re-editing a canvas refreshes last-touched so its media is no longer expired; a dry run lists orphans and expired media without deleting anything and the same scan reports both sets; downgrade cleanup deletes oldest-first until usage drops back under the free limit instead of wiping everything.
- Admin console: filtering users by email, status, and `planId` shows both buckets, `paidUntil`, plan, and storage; banning revokes refresh tokens so the user is fully signed out within 15 minutes; resetting a password signs the user out everywhere; every `/api/admin/*` endpoint returns 403 for non-admin accounts and `/admin` routes redirect non-admins to the home page; orders can be filtered by status, provider, and user; the model editor offers controlled inputs for constraints, the price matrix, and promotions with a discount preview, and every pricing change is auditable.
- Account deletion: requesting deletion needs the password, is idempotent, and immediately blocks generation and top-ups while keeping browse and export; cancelling inside the cooling window restores the account; after expiry the account is anonymized (placeholder email and username, cleared profile and password, revoked tokens, soft-deleted business data); registering the same email afterwards creates a brand-new account.

## 图片分辨率尺寸表

选择分辨率和宽高比后，W/H 按下表填写，单位为像素。预设尺寸不受「16 倍数对齐」开关影响；该开关只控制手动输入尺寸时的对齐。最终生成尺寸以所选模型的实际输出为准。

| --- | ---: | ---: | ---: |
| **1:1** | **1024 × 1024** | **2048 × 2048** | **2880 × 2880** |
| **2:3** | 1024 × 1536 | 1360 × 2048 | 2336 × 3520 |
| **3:2** | 1536 × 1024 | 2048 × 1360 | 3520 × 2336 |
| **4:3** | 1024 × 768 | 2048 × 1536 | 3312 × 2480 |
| **3:4** | 768 × 1024 | 1536 × 2048 | 2480 × 3312 |
| **16:9** | 1536 × 864 | 2048 × 1152 | **3840 × 2160** |
| **9:16** | 864 × 1536 | 1152 × 2048 | **2160 × 3840** |
| **21:9** | 2016 × 864 | 2688 × 1152 | **3840 × 1648** |
| **9:21** | 864 × 2016 | 1152 × 2688 | **1648 × 3840** |

待验收：

- 在画布和图像工作台逐项切换 3 档分辨率与 9 种比例，W/H 应与表格一致，重新打开设置后仍选中正确档位；重点检查 1K 的 2:3、16:9、21:9 及对应竖图，以及 4K 的 1:1。
- 所有 4K 预设提交时均不应触发本地总像素或最长边限制；生成和编辑请求、调用脚本应收到所选像素尺寸。
- 分辨率为自动时保留比例选择，比例为自动时禁用 W/H；手动输入 W/H 后，对齐开关仍应按原有方式工作。
- Gemini 在质量为自动时，应将表中尺寸识别为对应的 1K / 2K / 4K；显式选择质量时维持原有优先级。视频尺寸设置应保持原有行为。

## Canvas and asset resource migration (phase 2, frontend)

- Canvas list: paging, keyword search, and sorting all run on the server; the network panel shows no request that loads every canvas at once. List responses contain no `data`, and the "N nodes · N connections" numbers match the counts after opening a canvas.
- Autosave: editing stops for about two seconds and the top bar shows "Saved"; continuous dragging still saves at most every 30 seconds; a failed save (offline) is visible and can be retried.
- Opening a canvas offline: the page stays put and offers a retry instead of treating the canvas as missing and jumping back to the list.
- Conflicts: with the same canvas open on two devices, B gets a conflict dialog after A saves; "Overwrite with my version" makes A see B's content after a refresh, and "Reload" discards B's local edits; renaming a canvas does not create conflicts for the other device.
- Resize and typing: resizing a node stays smooth and sends a single save after release; typing text behaves the same after the user stops.
- Assets: keyword (including text bodies), kind, and tag filters all hit the server, and tag candidates come from the first page response; selecting several tags requires all of them. The canvas side panel, asset picker, and the Agent `assets_list` tool also filter on the server.
- Generation history: the workbench history loads the next page on scroll and stops once `nextCursor` is null; deleting records and paging on shows no gaps. An empty history is expected until phase 4 adds the server-side writer.
- Video resume: refreshing the video page issues one `GET /api/generations?kind=video&status=pending` query to resume polling, separate from the paginated history.
- Media: images, videos, and audio in the canvas and workbenches all come from `/api/media/{storageKey}`; an unverified account gets `EMAIL_NOT_VERIFIED` on upload while the canvas itself still saves; retrying an interrupted upload with the same `storageKey` does not duplicate records.
- Export and import: canvas and asset exports download media per `storageKey`; imports upload media before creating canvases or assets, and images are intact afterwards.
- WebDAV and local data: the settings page no longer has a WebDAV tab and exported config files contain no WebDAV credentials; the Local storage panel only lists app state, Agent messages, and prompt cache. The browser no longer stores canvases, assets, generation records, or media binaries (existing local data is not uploaded automatically; export a canvas zip first if you need to keep it).
