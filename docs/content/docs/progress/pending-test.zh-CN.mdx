# 待测试

- 前端设计稿：`design/html/` 下共 23 个静态 HTML 设计稿（含总览入口 `index.html`、前台 11 页、后台 7 页、组件规范与画布主题对照），全部支持浅色/深色切换与移动端布局；关键交互均已 Mock 化（不调接口、随机成功/失败提示）：工作台生成流程（成功/失败/内容审核拒绝/取消三态）、登录注册表单校验与跳转、后台用户勾选批量赠送/封禁解封、模型上下架与移除、渠道连通测试、审核卡片通过拒绝移除、提示词上下架、活动结束/删除、订单取消、补偿弹窗、素材增删与批量操作、社区点赞计数、模型约束的自定义标签添加（带格式校验与去重）。另新增[设计稿与接口对照](/zh-CN/docs/progress/design-api-coverage)文档，记录设计稿与后端规划的覆盖对照、三处冲突与九项接口缺口；三处冲突已修订，内容审核方案已从阿里云付费服务改为开源方案（图片 NSFWJS、文本 Detoxify），相关规划文档与设计稿已同步。
- 本地代理：配置弹窗应在「渠道」和「偏好设置」之间出现独立的「本地代理」页签，开关默认关闭。打开后应显示 `npx @basketikun/canvas-proxy@latest` 启动命令（端口非默认时自动追加 `--port`）、复制按钮，以及默认 `http://127.0.0.1:23210` 的地址输入框，失焦时自动补全协议并去掉末尾斜杠；「测试连接」应只在命令已启动时成功。开启代理后，拉取模型列表、生图、生视频、生成文本（含流式输出）、生成音频、自定义调用脚本、视频任务轮询，以及生成结果图片和视频的下载都应经代理转发且功能正常，关闭后恢复直连。代理本身应原样转发请求方法、请求头、查询参数和请求体，SSE 响应按块透传不缓冲，`data:` 和 `blob:` 地址不受影响。
- 图像与视频尺寸设置：图像设置应将分辨率（`1k` / `2k` / `4k` / 自动）和宽高比（`1:1`、`2:3`、`3:2`、`4:3`、`3:4`、`16:9`、`9:16`、`21:9`、`9:21`、自动）拆成两项，并由二者计算 W/H。视频设置仍使用 `480p` / `720p` / `1080p`（以及自定义 p 值），比例为 `1:1`、`3:4`、`4:3`、`16:9`、`9:16`、`21:9`、自动，并由清晰度与比例计算 W/H。秒数应为 4–30 的滑杆，右侧显示当前秒数；比例为自动时应禁用 W/H。
- 视频内置请求：未配置调用脚本时，OpenAI 格式应按模板发送 `mode`、`first_frame`/`last_frame` 或 `image[]`、`generate_audio`、`watermark` 以及参考视频/音频，不再使用 `input_reference[]`；Gemini 格式应走 `predictLongRunning`，按模式发送 `image`/`lastFrame` 或 `referenceImages`，不再提示不支持视频。刷新后应能继续查询 Gemini 任务状态。
- 视频生成模式：视频设置应出现「首尾帧」和「全能参考」；1 张图按首帧、2 张图按首尾帧发送专门字段，超过 2 张即使选了首尾帧也按全能参考发送。内置请求和调用脚本的 `params.mode` 均为 `frames` 或 `reference`。
- Gemini 生图：Gemini 格式渠道和 Gemini 生图调用脚本应使用 `generationConfig.responseModalities: ["TEXT", "IMAGE"]`，比例和尺寸放在 `imageConfig.aspectRatio` / `imageConfig.imageSize`，不再发送 `responseFormat`。
- 视频调用脚本：能力为「视频」的模型打开「调用脚本」后应进入全屏分步配置；左侧按「看懂规则 → 让外部 AI 写 → 可用变量」展示，可用变量应包含 `videos`（参考视频 File 数组）和 `audios`（参考音频 File 数组）；「复制写脚本说明」应包含当前能力、可用变量、返回要求和写法约束。插入的模板应是带参数列表的 async function，并把 `params` 拆开；OpenAI 生图模板必须包含 `quality`、`size`、`count`、`background`。OpenAI 视频模板应使用 FormData，带上 `mode`、时长、尺寸、分辨率、配音、水印以及参考图/视频/音频；`mode=frames` 时应使用 `first_frame` / `last_frame`，`mode=reference` 时应使用 `image[]`，完成后轮询并下载 `/content`。把外部 AI 写好的脚本粘贴到右侧并保存后，画布连接参考视频或参考音频再生成时，脚本应能读取这些文件。
- 文档站导航与本页目录：手机宽度打开文档侧边栏时，顶部应显示当前文档分类及说明；展开后可在项目介绍、操作手册、开发文档、项目进度、商务合作和赞助支持之间切换，切换后分类标题及下方页面列表应同步更新；桌面端顶部分类栏保持不变，宽度达到 960px 时正文右侧应显示带层级折线的本页标题目录，点击可跳转，滚动时自动高亮当前标题；较窄宽度继续显示顶部折叠目录。
- Canvas Agent 生成流程引用：提示词仅包含已经通过 `referenceNodeIds` 传入的 `@[node:...]` 引用时，应直接把现有文本、图片、视频、音频或组节点连接到生成配置节点，不再创建重复的提示词文本节点；提示词包含普通文字时仍应创建独立的提示词文本节点。
- 视频画面截取：右键有内容的视频节点应显示「截取首帧」「截取尾帧」「截取当前帧」；三项操作应按视频原始比例在右侧生成并选中图片节点，同时建立视频到图片的连线；「截取当前帧」应使用播放器此刻停留的画面，截取过程不得改变原视频的播放位置。
- 文本节点：节点正文右上角不再显示「生图」按钮，文字内容应使用完整正文区域；节点上方工具条中的生图入口仍可正常创建生成配置。
- 多文本生成：生成次数大于 1 时只创建一个文本结果节点和一条来源连线；节点右上角显示实际生成成功的文本数量，点击后应像多图节点一样展开所有备选文本；点击「设为主文本」应立即替换正文，原主文本保留为备选，双击正文编辑后再次切换回来仍应保留修改。
- 组节点引用：组节点应使用透明、轻量的边框与标题样式，并显示右侧输出连接点；把组连接到生成节点后，组内有内容的图片、视频、音频、文本及可引用扩展节点都应作为输入，普通提示词面板的 `@` 列表应显示组内资源，生成配置的 `@` 列表应允许一次选择整组；组与单节点重复引用时不得重复发送同一资源。
- 多选打组：框选或点选至少两个节点后，应出现包住全部选中节点的圆角虚线框，框上方显示「打组」；点击后用组节点包住这些内容并保持原位置，随后选中该组。选中组后可通过顶部「解散组」、右键菜单或 `Ctrl/Cmd+Shift+G` 取消分组；已同属一组的节点再次多选时应显示「解散组」而不是再打一组。拖入组、组引用和左侧树形列表应继续可用。
- 节点参考栏：普通节点提示词面板、放大编辑器和生成配置输入框上方应显示当前输入节点；图片和视频显示缩略图并可悬停预览，文本、音频及扩展节点显示对应类型；组连接应展开显示组内每个有效内容节点，删除任一展开项都应断开整组连线。点击加号进入画布选择后可连续添加有效参考，已连接、目标自身、已通过组引用的组内节点及不可引用节点不可重复选择，按 ESC 或顶部提示返回输入框；新增连接后 `@` 列表应立即更新。
- 多图透明背景：展开包含透明 PNG 或 WebP 的多图节点时，主图与所有备选图的透明区域都应直接显示画布背景；切换主图前后不得出现白色或主题面板底色。
- 画布选择与平移：左下工具栏应能切换「选择」与「移动」模式并用图标显示当前模式；选择模式拖动空白区域应显示疏朗清晰的虚线框，虚线长度、间距和粗细在任意缩放比例下保持一致；移动模式应能从空白区域或节点上拖动画布。按住 Control 或空格应临时反转当前工具且不改变工具栏模式，即选择变移动、移动变范围选择；点击画布页任意按钮后按空格应只临时切换工具，不得再次触发该按钮；输入框和可编辑文本内仍可正常输入空格。中键平移以及 Shift/Cmd 追加选择节点应继续可用。
- 文档站国际化：访问文档站首页及 `/docs` 应直接显示英文，不得出现重定向循环；切换简体中文后 URL 应带 `/zh-CN` 且首页、顶部导航、侧边栏、正文、搜索框和页面操作文案均显示中文；刷新、站内跳转和再次切回 English 后语言应保持正确，搜索结果与 Markdown/LLM 文档内容不得混入另一种语言。
- 国际化基础框架：从页面右上角切换简体中文或 English 后，首页、顶部及移动端导航、版本弹窗、配置主面板、渠道编辑、模型选择、页面标题、页面描述和 Ant Design 内置文案应立即切换，刷新页面后保持所选语言；偏好设置中不应再显示语言选项，提示词来源及其他尚未接入翻译的业务模块暂时仍可能显示中文。
- 全局弹层主题：全站 Dropdown、Menu、Select、Cascader、TreeSelect 等弹层在浅色主题下应使用白色背景、轻灰悬停和选中态，在深色主题下应使用深色背景与低对比度浅色交互态，不应再出现默认黑灰色块、文字对比不足或单个页面配色不一致。
- 画布节点缩放稳定性：选中任意节点并反复拖动四角缩放时，节点工具条应在缩放期间隐藏、松开后恢复，页面不应再出现 `Maximum update depth exceeded`。
- Agent MCP 初始化状态：首次进入空白对话、点击「新对话」或恢复历史对话后，无需先发送消息，对话区应立即显示 Codex 会话准备，并列出 `codex_apps`、`infinite-canvas`、`node_repl` 等完整 MCP 服务状态；全部服务进入终态前可输入并保留草稿，但发送按钮、上传和回车提交应禁用；可选 MCP 失败时应提示警告但允许发送，`infinite-canvas` 缺失或失败时应阻止发送并显示明确原因；首轮及后续任务运行期间再次收到的 MCP 状态只进入诊断日志，模型开始处理及回复完成后对话区不应残留初始化卡片。
- Agent 模型设置：连接 Canvas Agent 后，输入框左下方应显示当前 Codex 模型与推理强度；模型列表应来自当前账号实际可用模型且不显示内部审查模型或重复项，切换模型后强度选项随模型能力更新且无空白选项，刷新页面后保留选择，发送任务时实际使用所选模型和强度；本地控制台与右侧「日志」应记录本轮使用的模型和推理强度。
- Agent 新对话响应：一轮对话完成后点击「新对话」，聊天内容应在服务端确认切换后清空并进入空白对话；后台应串行创建线程并预热 MCP，多个标签页应按同一会话版本同步，旧 HTTP 响应不得覆盖较新的 SSE 状态，初始化完成前不能发送到上一条会话或重复创建线程；重启 Agent 后应重新恢复并预热已有活动线程，无法恢复的失效空线程应自动替换为可用的新线程。
- Agent 读取画布卡片：读取当前画布完成后，卡片应按非零类型显示文本、图片、配置、视频、音频、分组、其他节点及连线数量，例如「3 个文本、5 张图片、2 个配置、4 条连线」；空画布应显示「当前画布为空」，执行失败时仍应显示错误信息，刷新恢复历史后统计保持一致。
- Agent 首次发送响应：在空白新对话中输入内容并按回车后，输入框应立即清空、用户消息应立即出现在对话中，再显示「正在思考」；线程创建或发送失败时，原输入和附件应恢复；任务运行期间输入的新草稿不应在请求成功后被清空。
- Agent 动态工具信息：执行内置生图、查看图片、命令、文件修改或其他动态工具时，卡片标题应显示具体工具名称；执行失败时正文应显示真实错误原因，刷新并恢复历史对话后仍应保持一致，不再统一显示「工具操作已完成」。
- Agent 画布生图：重启 Canvas Agent 后，其自动生成的工作区 `AGENTS.md` 应同步为最新版指令（用户自行编写的其他 `AGENTS.md` 不应被覆盖）；输入“生成一张图片”时应调用 `canvas_generate_image`，通过当前画布节点创建并运行生成流程；只有明确输入“使用 Codex 内置生图/ImageGen 技能生成”时才允许调用内置能力，Codex App Server 返回的 `imageGeneration` 结果应显示在对话中并作为保持原比例的图片节点添加到当前画布；Agent 不应在没有生成结果时提前声称“已生成”。
- Agent 顶部栏：在对话、历史和日志之间新增「技能」标签并显示已加载数量；连接状态应位于左侧 Agent 标题旁，并与右侧新对话使用相同规格的文字按钮，只有内容标签显示选中线；标签图标始终显示，中英文模式下都应按标签区域的实际可用宽度隐藏文字并保留小号数量，空间足够时显示图标和文字，拖动宽度时不应裁切、换行、横向滚动或错位。
- Agent 输入框窄屏布局：底部上传、Skill、确认模式、权限模式、模型和思考程度控件在窄面板下应只显示图标，宽面板下恢复文字；所有纯图标操作悬停时应使用统一样式显示名称或当前状态，任意宽度都不出现横向溢出。
- Agent 本地 Skill 管理：连接 Canvas Agent 后进入「技能」，应能读取当前 Codex 工作空间发现的项目、个人、系统和管理员 Skill，并支持搜索、按范围筛选、刷新及启停；未能加载的 Skill 应通过可点击、可滚动的详情查看原因；画布在站点工作空间 `.agents/skills` 下创建的 Skill 应可新建、编辑和删除，其他来源只读且不得被画布改写；编辑期间文件被其他窗口修改时应拒绝覆盖，清空显示名称、短说明和默认提示词后旧值应被删除，同时保留图标、品牌色等未由当前界面管理的元数据；多个标签页同时连接时，任一页面的 Skill 变更应自动同步，断开或切换 Agent 时旧请求不得重新写回列表或弹出编辑器。
- Agent Skill 草稿生成：创建 Skill 时应提供「空白创建」「从当前对话生成草稿」「从当前画布生成草稿」三种入口；空对话不得发起生成，取消时不得写入文件，确认后才写入站点工作空间 `.agents/skills`；Agent 运行中应禁用生成，多标签页下对话和画布来源必须分别严格绑定发起请求的 `threadId` 和 `clientId`，生成期间外部 MCP 仍应操作最近聚焦页面；草稿运行时创建、启停、删除和更新 Skill 应被统一拒绝，点击停止应真实中断临时草稿 turn；草稿不得泄露本地路径、密钥、媒体数据、真实节点 ID 或任务进度等临时状态，普通中文斜杠文本与 `/imagine` 等命令必须保持完整，生成草稿使用的临时 turn 不得出现在 Agent 对话、历史或日志中。
- Agent Skill 调用：在技能页点击「使用」或在输入框输入 `/` 搜索并选择 Skill 后，Skill 应作为原子 token 插入正文，而不是显示在输入框上方；发送任务时应通过 Codex 原生结构化 Skill 输入执行，发送成功后清除选择，失败时保留；新建对话、断开连接、Skill 被停用或删除时也应清除失效选择，发送前、任务完成后和刷新历史后的用户消息文字与 token 位置应保持一致。
- Agent 输入框快捷引用：输入 `/` 后应显示已启用 Skill 列表，输入 `@` 后应显示当前画布的图片、视频、音频和文本素材，长列表使用较高的内部滚动区域；选中项应按当前光标位置插入正文，例如「这是第一张图 `@图片1` 融合第二张图 `@图片2`」，不再集中显示在输入框上方，按 `Backspace` 或 `Delete` 时应整块删除；发送时应保持原句顺序，按节点 ID 精确引用发起页面的素材，并把引用图片的实际内容交给 Codex；输入框和聊天记录都应将引用渲染为与正文基线对齐的紧凑标签，悬浮或聚焦后可预览图片、视频、音频或文本内容，不重复显示内部图片附件，切换会话或刷新后引用样式应保持；可用方向键、`Enter` 或 `Tab` 选择，`Esc` 应关闭候选菜单，候选菜单打开时回车不得误发送消息。
- Agent 消息元数据：发送包含图片附件、Skill 或画布引用的消息后，刷新当前页面、在另一页面恢复同一对话或重启 Canvas Agent，历史消息都应由 Agent 按准确的 `clientMessageId`、`threadId` 和 `turnId` 恢复展示，本地缩略图仍可悬浮或点击查看，不依赖浏览器 IndexedDB 或文本匹配；通信协议版本变化不得清空独立的消息存储，遇到未知版本或损坏清单时应拒绝写入且保留原文件；删除线程后对应缩略图和引用元数据应同时删除，不得按记录数量或文件大小静默裁剪，改动前仅存在于浏览器旧缓存中的消息继续显示普通文本且不尝试迁移。
- Agent Markdown 样式：右侧 Agent 回复中的代码块应为横向占满消息区域、无语言标题和无双层边框的紧凑代码条，单行内容不应保留纵向大面积空白，复制操作仅在悬停时弱化显示；行内代码、链接在浅色和深色主题下应清晰；点击外部链接后应显示中文紧凑确认弹窗，长路径能够正常换行且复制、继续打开和关闭操作可用；点击 `/Users/`、`/home/` 等本地绝对文件路径时应改为提示在系统文件管理器中定位，支持复制路径，且浏览器地址不应跳转为 localhost 文件路径。
- Agent 工具确认模式：右侧面板标题栏不应再显示「工具确认」开关；对话输入框左下方应显示确认模式选择，默认选中「自动确认」，画布写入工具应直接执行；切换为「手动确认」后，画布写入工具应在对话中展示等待确认卡片，并支持批准或拒绝。
- Canvas Agent Codex 升级：启动 Canvas Agent 后应输出 Canvas Agent、内置 Codex 和本机 Codex 版本，实际运行的内置 Codex 应为 0.146.0；内置与本机版本不一致、未安装本机 Codex，或 npm 存在更新版本时应显示对应升级提醒，npm 检查失败不应阻止服务启动；Agent 应能正常连接 Codex、创建或恢复会话、发送消息并调用画布工具，运行中停止任务应只中断当前 turn，随后无需重启 Agent 即可继续发送新任务。
- Canvas Agent Debug：普通启动应通过公共 logger 输出 Info、Warn 和 Error 日志；使用 `npx -y @basketikun/canvas-agent@latest --debug` 启动后还应输出 Debug 日志并显示日志文件路径，终端统一采用“`YYYY-MM-DD HH:mm:ss` 级别 消息 详情”的纯文本单行格式，`~/.infinite-canvas/logs/` 下应按启动日期生成相同格式的 `canvas-agent-YYYY-MM-DD.log`，同一天多次启动应追加到同一文件；日志中不应出现连接 token 或图片 Data URL 原文。
- Canvas Agent 凭据脱敏：Codex 与 Claude CLI 的 stderr 包含 Bearer token、`sk-` 密钥、显式 API key/token/authorization 赋值、ANSI 样式或跨输出分片的凭据时，调试日志和网页诊断事件均不应出现明文；普通 stderr 文本应保持不变。
- Canvas Agent 配置权限：在 Linux 和 macOS 上保存配置后，`~/.infinite-canvas` 权限应为 `0700`，`canvas-agent.json` 权限应为 `0600`，已有的宽松权限也应被纠正；配置应能继续正常读写，Windows 启动不受影响。
- Canvas Agent URL 自动连接：链接应在 `#` 后传递 `agentUrl` 和 `agentToken`，进入或选择具体画布时继续保留，读取后立即从地址栏移除，并可连接有效的本机、局域网或远程 HTTP(S) Agent 地址且不主动展开设置面板；缺少参数或地址无效时应展开设置并显示错误。
- 图片 API 模型参数：`gpt-image-*` 的生成和编辑请求不应发送 `response_format`，`dall-e-*` 请求仍应发送 `response_format: "b64_json"`。
- 多参考图编辑：OpenAI 格式在多张参考图时应使用重复的 `image[]` 表单字段提交文件，单张参考图仍使用 `image`；新建的 OpenAI 图片脚本应使用相同字段名。Gemini 渠道和已经保存的自定义脚本不受影响。
- Canvas Agent Codex 日志：Codex app-server 输出带颜色或样式控制符及 UTC 时间的 stderr 时，本地日志和网页诊断日志应只显示一份 `YYYY-MM-DD HH:mm:ss` 本地时间和干净文本，不应出现重复 ISO 时间或 `[2m`、`[31m` 等 ANSI 转义内容。
- Agent HTTP 诊断日志：网页发送一条普通消息后，本地 Debug 日志不应重复输出 `/health`、`/canvas/state`、`/canvas/activate` 成功请求、流式增量或完整会话响应，只保留 HTTP 请求与 Codex 生命周期摘要；右侧「日志」应以单行时间线展示发送、开始、回复、工具、完成用量和错误，不再输出 userMessage started/completed、流式摘要、重复 threadId 或大段原始 JSON。
- Agent 排查日志：右侧「日志」中的排查视图应显示连接摘要，并可按错误、警告和信息筛选；向下查看日志时仅列表内部滚动，标题、连接状态、筛选数量和操作按钮保持固定；连续相同事件应折叠计数，单条日志可展开查看完整详情；原始 JSON、复制全部、复制最近错误和清空功能应继续可用，浅色与深色主题下均应清晰。
- Agent 排查日志顺序与跟随：日志应按时间从旧到新排列，进入日志或切换筛选时定位到最新事件；停留底部时自动跟随新日志，展开最后一条后应继续停留在完整详情底部，向上浏览后暂停跟随并显示与对话区视觉高度一致的居中圆形向下箭头，新日志数量只在悬浮提示中显示；列表底部不应出现额外留白，点击按钮后回到底部并恢复跟随。
- Agent 对话统计：用户消息应右对齐并使用透明无气泡的简洁排版，用户和 Codex 两侧均不显示人物头像，消息下方均不显示时间或 Token 信息；输入框上方应居中展示最新一次模型调用的输入、缓存、输出 Token 用量，不显示会话累计值，数值更新时应从旧值平滑滚动到新值而非突然跳变，新建、切换或删除当前会话后应清空旧统计。
- Agent 回复实时显示：在右侧 Agent 发送消息后，用户消息下方应立即出现“正在思考...”，任务运行期间不应闪退；工具完成后应显示 Codex 正在继续处理及已等待时长，等待超过 30 秒时提示可继续等待或停止本轮；Codex 的回复应在当前对话中持续显示，实时事件缺失时也应在任务完成后自动同步完整内容，无需切换到历史或日志再返回对话。模型繁忙等任务失败时应立即结束等待状态，在对话中显示中文错误原因和重试建议，诊断日志不应再把失败轮次记为“处理完成”，刷新历史后错误仍应保留。新建尚未发送首条消息的空会话不应反复出现历史读取失败。
- Agent 对话实时与历史一致性：运行包含思考、命令及画布工具的较长任务，在执行中刷新发起页面或打开第二个页面时，已出现的用户消息、思考过程、工具卡和回复前缀均应保留并继续更新；同一思考或工具只显示一张卡片，任务结束及再次刷新后内容、顺序和状态应一致。切换页面焦点不能改变本轮画布工具目标，发起页面断开后不得把图片或写操作转交其他画布，使用相同页面身份重连后才能继续处理。
- Agent 流式交互性能：发送长回复时文字应连续平滑出现，输入框、滚动和画布操作不应随回复变长而明显卡顿；长历史会话中只有当前流式消息持续更新，屏幕外消息不应造成明显布局压力；任务完成后应通过 SSE 自动同步完整历史，不再持续请求 `/health` 轮询状态。
- Agent 过程时间线：新建 Agent 对话后 Codex 应生成可读思考摘要，并在运行时依次显示中文的思考摘要、执行计划、命令执行、网页搜索、文件修改和画布工具活动；思考摘要的图标、标题和箭头应稳定保持在同一行，默认收起且无边框，点击箭头后才展开 Codex 实际返回的具体摘要，其中 Markdown 强调、列表和代码应正确渲染而非显示原始符号，多行代码块和文本流程图应保留原始换行并允许横向滚动，完成事件不应再用「已完成分析」覆盖已经收到的摘要；同一轮连续命令应合并为显示数量的无边框折叠行，折叠时不显示命令预览，单条展开后直接显示详情，多条展开后可逐条查看工作目录、耗时、退出状态和运行输出；其他工具调用继续使用紧凑卡片排版，状态图标、标题和状态文字保持在同一行；结构化任务进度不应混在对话时间线中，而应独立放在对话区下方、Token 统计上方，支持展开和折叠，并逐项实时更新「待处理」「进行中」「已完成」状态；新任务生成时默认展开，任务结束后保留最新结果，同一计划更新不应生成重复内容；文件详情展示文件路径与新增/修改/删除动作，工具详情不应出现请求 ID、英文工具名或原始 JSON；一轮对话结束自动同步历史以及刷新页面后从历史中 resume 对话时，思考摘要、命令和工具过程记录仍应完整保留并保持相同展示。
- Agent 权限控制：输入框可选择「请求批准」「自动审查」「完全访问」；请求批准模式下，Codex 编辑工作区外文件、执行受限命令或访问网络时应在对话中显示审批卡片，支持拒绝、允许一次和本会话允许，并能依次处理多个并发请求；提交决定后卡片应保持禁用等待，只有 Codex 确认处理后才移除；等待审批时刷新页面，未处理的审批卡应自动恢复且不能让任务永久卡住；自动审查模式应仅将需要用户决定的风险操作送入审批；完全访问必须先显示风险确认，启用后可访问网络和本机文件且不再请求审批；选择应在刷新后保留。
- Agent 历史记录：点击记录卡片应直接进入对应对话，不再显示「进入」按钮；可勾选单条或全选多条记录并批量删除，删除当前对话后聊天内容应清空。
- Agent 默认新对话：每次进入任一画布并连接 Agent 后，对话区应保持空白且不自动恢复上一次会话，并在后台创建新线程、预热 MCP；需要继续旧对话时可在「历史」中主动选择恢复。
- Agent 当前画布优先：在已打开某个画布时要求 Agent 创建、修改、整理或生成内容，Agent 应直接读取并操作当前画布，不应先调用 `canvas_list_projects` 或使用 `site_navigate` 重复进入画布；只有明确要求查看或切换其他画布时才允许查询画布列表并导航。
- Agent 图片消息：发送一张或多张图片附件后，图片应紧跟用户文字并在消息右侧显示为约 40px 的紧凑缩略图，不再撑大消息区域，单击缩略图应打开大图预览，打开或关闭预览不应改变消息间距或产生额外空行；任务运行中、完成同步历史、切换页面及重新进入历史对话后都应显示浏览器本地保存的图片缩略图，不应消失或把 attachmentId、附件使用说明等内部上下文回显到用户消息中；删除历史会话后应同步清理对应缩略图。
- 画布文本复制：在 Agent 对话或节点信息详情中用鼠标选中文字后，按 `Ctrl/Cmd + C` 应复制所选文本，不应触发画布节点复制；未选中文字且焦点位于画布时，原有节点复制快捷键应保持可用。
- Agent 工作目录指令：`canvas-agent/agent-instructions.md` 应作为独立维护源；重启 Canvas Agent 后，当前工作目录应自动生成 `AGENTS.md`；新建对话发送消息时，Codex 日志中的用户消息只包含本轮请求和必要的附件上下文，不再重复整段 Infinite Canvas 前置提示词，画布及工作台工具仍可正常调用。
- 画布文本设置：文本节点和生成配置节点切换到文本模式后应显示推理强度设置，可选择自动、低、中、高、极高；选择自动时默认 OpenAI Responses 请求不应携带 `reasoning`，选择其他档位时应携带所选强度，刷新画布后节点设置应保留；文本模型自定义调用脚本应能读取 `reasoningEffort`，OpenAI 模板应按自动或指定档位正确组装请求。
- 生图工作台参考图：将一张或多张图片拖入参考图区域后应直接上传并显示缩略图；拖入非图片文件应忽略，拖动过程中区域应显示高亮提示，放下文件不应导致浏览器打开或替换当前页面。
- 工作台历史图片清理：生图或视频工作台生成内容后，在「我的素材」删除图片、删除画布图片节点、清空画布或删除画布，再次打开对应生成记录时，历史缩略图、结果图片和参考图仍应正常显示；删除生成记录时，其专属本地文件仍应正常清理。
- 视频创作台参考资产：将图片、MP4/MOV 视频或 MP3/WAV 音频拖入任一参考资产区域后，应按文件类型自动上传到对应列表；当前拖入区域应显示高亮提示，原有数量、大小、时长和格式限制应继续生效。
- 画布组装提示词：输入或连接超长提示词后，浮层正文高度不应继续撑大，内容应可在正文区域内滚动查看和编辑，标题及关闭按钮保持可见。
- 画布节点提示词：图片等节点下方的提示词超过输入区域高度后，鼠标悬停在输入区域内滚动应查看提示词内容，不应缩放画布。
- 画布节点提示词回显：单图或多图生成完成后，切换选择生成结果的根节点及任一子节点，下方输入区域都应继续显示生成时的提示词；切换到其他节点再选回来后也不应清空。
- 画布生成配置：连接文本节点后连续点击生成（包含失败重试），组装提示词不应重复追加上游文本；在生图、文本、视频、音频之间切换时，实际请求应始终使用当前面板展示的对应类型模型。
- 画布多图生成：开始生成 N 张图片后应立即创建一个包含 N 个可展开槽位的图片节点，并且来源到结果只保留一条连线；生成期间空槽位应独立显示生成中或失败，任何已有图片内容的槽位都必须始终显示图片，任意图片率先成功后应立即成为主图并展示，不等待其他请求完成；收起状态应最多显示三层紧密错开的背板，避免占用过多画布空间，右上角应显示醒目的「N 张」数量提示；点击数量后，浮动工具条应暂时隐藏，各图片槽位应从当前节点向右上方整齐展开；已成功图片的「设为主图」应常驻显示，并在亮色、深色主题及不同图片背景上保持清晰；点击画布空白处应自动收起并恢复工具条。
- 画布多图主图切换：点击「设为主图」后，节点中心和当前最长边应保持不变，仅按新图片比例调整另一条边；自由变形节点应完全保持现有宽高，画布视口及左下角缩放值不应变化。
- 画布多图失败槽位：包括当前主槽位在内的每个失败槽位都应显示「重试」和「删除」；重试只更新当前槽位，已有成功主图时不得抢占主图；删除只移除当前失败槽位并同步更新图片数量。
- 画布多图尺寸调整：子图展开时开始拖动尺寸控制点，应先收起图片组一次，再正常调整根节点尺寸，不应触发 React 循环更新或应用错误页。
- 画布左侧元素列表：点击元素整行应平滑定位并选中对应节点，自动缩放不得超过 100%；有内容的图片元素应显示预览按钮，点击后打开大图弹窗且不触发画布定位。
- 生成提示词的文本编号：普通节点或生成配置连接多个文本节点后发起生成，附加在提示词末尾的每段上游文本都应以「【文本1】」「【文本2】」开头并按连接顺序编号，编号与提示词里 `@` 引用及参考内容栏显示的一致；单段文本同样要带编号，图片、视频、音频编号不受影响。
- 局部遮罩编辑：弹窗底部应为「重置」「导出到画布」「立刻生成」；两个按钮都要求已涂抹区域并填写修改要求，「导出到画布」只写入节点和连线不发起请求，结果节点的提示词面板应预填拼好的提示词并可手动生成，「立刻生成」在写入节点后立即生成。涂抹区域并填写修改要求后确认，画布应在原图下方生成一个「遮罩标注」图片节点，内容为原图叠加半透明蓝色标注区域，颜色和透明度应与弹窗里涂抹时看到的一致；结果节点在原图右侧生成，并同时接收来自原图和遮罩标注的两条连线。请求应按普通参考图发送两张图片，提示词按「图片1 / 图片2」编号说明原图和标注区域，不再携带 mask 参数，Gemini 格式渠道也应可用；生成结果只改动标注区域，且不得残留蓝色标注。

## 内容审核与人工复核（第五期）

- 输入预审：违规提示词或参考图返回 422 `CONTENT_REJECTED`，不扣点数与免费次数、不写消费流水、不调上游，并保留用户已输入内容；审核记录只存内容哈希与标签，不存原文。
- 产物审核：图片与视频先进入隔离区，审核通过后才获得正式 `storageKey`；违规产物用户不可读取，生成记录显示 `rejected`，点数不自动退还（误判走人工复核与赠送桶补偿）。
- 上传审核：违规参考图与素材在上传时被拒，不进入正式桶、不增加存储用量；同一 `storageKey` 重试幂等，上传中断不会在用户媒体列表里留下残留。
- 隔离区：管理员可短期预览仍有效的原件，预览地址不能被普通用户复用；隔离期到后原件物理删除，哈希与摘要仍保留。
- 人工复核：可按阶段、结论、标签、复核状态与时间筛选；两名管理员先后复核同一记录，第二人收到 revision 冲突；通过时若隔离原件仍在有效期内会释放到正式存储，已过期时明确提示无法恢复。
- 补偿：进入 `granted` 桶、不改变付费身份、关联审核记录 id，同一记录不能重复补偿。
- 故障策略：超时、429 与 5xx 按 `MODERATION_FAIL_MODE` 处理；`reject` 不预扣、不调上游、不提交上传，`allow` 只在明确配置后放行并记录 `error` 与告警；开启审核但未配置 fail mode 时 API 拒绝启动。
- 运维：管理统计页展示通过率、拒绝率、错误率、标签分布、复核积压、改判率与隔离区用量；审核服务不可用时日志出现 `MODERATION_ALERT`。
- 文案边界：对外只承诺站内生成与上传链路已审核，不扩大到用户导出内容与设备本地内容。

## 服务端 AI 转发（第四期）

- 单一路径：任意页面的任意生成请求在浏览器网络面板里只打到本站 `/api/ai/*`，没有任何指向第三方域名的请求；localStorage、sessionStorage 与内存里都找不到 API Key。
- 报价：价格表完整展示合法组合的点数与人民币；折扣按具体度再按优先级取一条且不叠加；凭证有效期不晚于活动结束，活动被停用、修改、覆盖或价格矩阵变更后旧凭证返回 409 `QUOTE_STALE`，且没有预扣、没有调上游。
- 参数校验：传 `constraints` 外的参数返回 400 `PARAM_NOT_SUPPORTED` 并带 `param` 与 `allowed`；用视频模型调 `/api/ai/images/generations` 返回 400 `MODEL_NOT_SUPPORTED`；切换模型后非法已选值自动回落为合法值。
- 扣点一致性：余额不足返回 402 `INSUFFICIENT_CREDITS` 并带 `requiredMicros`、`availableMicros` 与 `shortfallMicros`，不发起上游请求；把平台渠道 Key 改错后生成返回 502，点数全额退还并写入一条 `type=refund` 流水；同一 `idempotencyKey` 连发两次只扣一次；缺少 `idempotencyKey` 返回 400 且没有扣点。
- 流式：文本逐字出现（必须在 nginx 后面测，不能直连 8080）、上游长时间沉默不被掐断、点停止后 1 秒内关闭上游连接、连续 20 次流式对话不会泄漏并发槽位。
- 视频：创建任务时写入 `pending` 生成记录并立即扣点，关掉页面任务仍会跑完并收敛为 `succeeded`；刷新页面后工作台仍能按生成记录里的任务句柄继续显示进度；任务失败只退还一次；生成过程中杀掉 `api` 进程，重启后滞留请求被收敛、视频任务继续轮询到终态。
- 结果落地：图像、视频、语音都以 `storageKey` 返回并由 `/api/media/...` 渲染；等第三方 URL 过期后画布里的视频仍能播放；存储超额返回 507 且点数已退还；未验证邮箱在预扣前就返回 403。
- 安全：让上游返回指向内网的结果 URL、或先公网再 302 跳到内网，服务端都会拒绝下载；后端日志里搜不到任何 API Key；管理后台渠道接口只返回 `hasKey`，不返回明文。

## 点数、支付与管理后台（第三期）

- 账本：管理后台向 `granted` 桶加点后只有 `grantedMicros` 增加，流水带正确的桶、金额与写入后余额，档位仍为 `free`；按桶 `SUM(amount_micros)` 始终等于两个桶；把某个桶扣成负数会被拒绝且余额与流水都不变；流水没有任何写接口。
- 档位与配额：只有赠送点数的账号保持 `free`；充值后 `/api/me` 立即显示 `paid` 与更大的存储、单文件与保留期上限，全程无需管理员操作；购买桶耗尽但权益期内仍为 `paid`，到期后先进入 60 天 `sunset` 再落 `free`；用量超过派生档位上限时 `readOnly` 为 true，上传返回 403 `READ_ONLY`（响应带 `planId`），浏览、编辑、删除与导出仍可用；超出档位上限的上传返回 507 `STORAGE_QUOTA_EXCEEDED` 并带 `used` 与 `limit`；并发上传后 `usage.storageBytes` 与 `SUM(media_files.bytes)` 一致。
- 订单与回调：管理员修改档位后已创建订单快照不变；同一 `provider_order_id` 重复回调只到账一次，第二次仍返回渠道要求的成功响应；伪造签名返回 400 `INVALID_SIGNATURE`；金额不一致时拒绝到账并记录日志；取消已支付订单返回 409 `ORDER_ALREADY_PAID`，用他人订单 id 取消返回 404；待支付订单超过 30 分钟先向渠道主动查询、确认后再置失败；连续充值两次时 `paid_until` 从原截止时间继续延长而不会缩短。
- 模型目录与折扣：新增模型后模型广场立即出现且参数表单按 `constraints` 渲染；去掉 `quality` 后不再渲染质量选择器；切换模型时非法已选值自动回落；价格表列出全部组合且每次组合变化都能看到对应价格；保存时拒绝缺组合、重复、负价格与 `constraints` 外的取值；折扣按具体度再按优先级取一条且不叠加；冲突规则返回 409 `PROMOTION_CONFLICT`；停用或修改活动会递增版本，`nextPricingChangeAt` 到点后价格矩阵自动刷新；已产生过流水的模型无法删除只能下架，充值档位没有删除入口。
- 清理与注销：删除画布后对用户执行清理，只删除其独占媒体并降低用量；软删除画布引用的媒体不会被清理；重新编辑画布刷新最后触达后该媒体不再计入过期；预演只列出孤儿与过期项、不删除任何文件，同一次扫描能看到两个结果集；降档清理按最旧优先删到用量回落到免费上限内，不会删光。
- 管理后台：按邮箱、状态与 `planId` 筛选用户，列表展示两个桶、`paidUntil`、档位与存储用量；封禁会撤销刷新令牌，最多 15 分钟完全掉线；重置密码会把该用户全部设备踢下线；非管理员访问任意 `/api/admin/*` 返回 403，访问 `/admin` 路由被重定向到首页；订单可按状态、渠道与用户筛选；模型页用受控表单编辑约束、价格矩阵与折扣活动并可预览折后价格，价格变更都有审计记录。
- 账号注销：申请需要校验密码且重复申请幂等，申请后立即无法生成与充值但仍可浏览与导出；冷静期内撤销后账号恢复；到期后账号被匿名化（占位邮箱与用户名、清空资料与密码、撤销令牌、业务数据软删除）；之后用原邮箱注册得到全新账号。

## 画布与素材的资源化改造（第二期前端）

- 画布列表：翻页、关键字搜索与排序都由服务端完成，网络面板里看不到一次性拉取全部画布的请求；列表响应不含 `data`，卡片上「N 个节点 · N 条连线」与实际打开画布后的数量一致。
- 自动保存：编辑画布停手约 2 秒自动保存、顶栏显示「已保存」；持续拖动节点不停手时最多 30 秒也会保存一次；断网后保存失败有提示且可点击重试。
- 断网打开画布：页面停在原处提示重试，不会被当成「画布不存在」跳回列表页。
- 冲突：两台设备打开同一张画布，A 保存后 B 保存会弹出冲突选择框；选「用我的版本覆盖」后 A 刷新看到 B 的内容，选「重新加载」后 B 丢弃本地改动看到 A 的内容；重命名画布不会让另一台设备产生冲突。
- 缩放与输入：缩放节点时不卡顿、松手后只发一次保存；连续输入文本同样只在停手后发一次。
- 素材：关键字（含正文关键词）、类型、标签筛选都命中服务端，标签候选来自列表第一页响应；标签多选为「同时包含」；画布侧栏、素材选择弹窗与 Agent 的 `assets_list` 同样走服务端筛选。
- 生成记录：工作台历史滚动到底自动加载下一页，`nextCursor` 为 null 后停止请求；删掉本地记录后继续翻页不出现空洞；生成历史为空属预期（服务端写入在第四期接入）。
- 视频任务恢复：刷新视频页会发出一次 `GET /api/generations?kind=video&status=pending` 查询用于恢复轮询，与历史分页是两个独立请求。
- 媒体：画布与工作台里的图片、视频、音频均由 `/api/media/{storageKey}` 提供；未验证邮箱的账号上传媒体返回 `EMAIL_NOT_VERIFIED` 但画布本身仍能保存；上传中断后用同一 `storageKey` 重试不会产生重复记录。
- 导出导入：画布导出与素材导出会按 `storageKey` 逐个下载媒体；导入时先上传媒体再建画布/素材，导入后图片不破图。
- 本地数据：「本地存储」面板只显示应用状态、Agent 消息与提示词缓存，浏览器 IndexedDB 里不再保存画布、素材、生成记录与媒体二进制（升级后旧数据不会自动上传，需要保留可先导出 zip 再导入）。
