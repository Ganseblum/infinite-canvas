# 项目结构

本文档说明仓库的整体结构、各子项目使用的技术栈，以及核心模块之间的关系，帮助开发者或 AI Agent 快速建立全局认知。

功能的使用说明见 [功能介绍](/zh-CN/docs/overview/features)，画布本地数据格式见 [画布数据结构](/zh-CN/docs/development/canvas-data-structure)。

## 仓库总览

仓库包含四个子项目，各自独立安装依赖，没有统一的 workspace 配置。

| 目录 | 说明 | 运行方式 |
| --- | --- | --- |
| `web/` | 主应用，浏览器端无限画布 | Vite 开发服务器 / 静态站点 |
| `canvas-agent/` | 本地 Agent 服务，连接 Codex / Claude Code | 本机 Node 进程 |
| `docs/` | 文档站（即本站） | Next.js 服务 |
| `plugins/` | 画布节点插件、插件 SDK 与 Codex app 插件 | 构建产物，被上面两者消费 |

其余顶层内容：

| 路径 | 说明 |
| --- | --- |
| `AGENTS.md` | AI / 自动化开发约束，改动代码前需遵循 |
| `CHANGELOG.md` | 变更日志，`Unreleased` 记录未发版改动 |
| `VERSION` | 当前版本号，构建时注入前端 `__APP_VERSION__` |
| `Dockerfile` / `docker-compose*.yml` / `nginx.conf` | 前端容器化部署 |
| `vercel.json` / `render.yaml` | Vercel、Render 平台部署配置 |
| `.github/workflows/` | CI：Pages、Docker 镜像、文档镜像、官方插件发布 |
| `.agents/` | Codex 插件市场配置与本地 skills，由 `skills-lock.json` 锁定 |
| `assets/` | README 中的赞助商等图片资源 |

## 整体架构

浏览器是所有业务的执行主体，没有项目自建的后端服务：画布数据存在本地，AI 请求由前端直连用户配置的接口，本地 Agent 只在需要让 Codex 操作画布时才启动。

```text
                    ┌──────────────────────────────┐
                    │  浏览器（web/）               │
                    │  画布 / 工作台 / 提示词 / 素材 │
                    └───┬───────────┬──────────┬───┘
                        │           │          │
        IndexedDB       │      直连 HTTPS      │  HTTP + SSE
      localStorage ◄────┘           │          └─────────────┐
      （画布/素材/配置）             ▼                        ▼
                          OpenAI 兼容接口          canvas-agent（本机 127.0.0.1）
                          GitHub 提示词仓库                  │ stdio JSON-RPC
                          WebDAV（可选同步）                  ▼
                                                    Codex app-server / Claude CLI
                                                             │ MCP
                                                             └──► 回调画布工具
```

## web/：前端主应用

### 技术栈

| 分类 | 选型 |
| --- | --- |
| 构建 | Vite 7、`@vitejs/plugin-react`、TypeScript 5 |
| 框架 | React 19.2.5 |
| 路由 | React Router 7 |
| 状态 | Zustand 5、TanStack Query 5 |
| UI | Ant Design 6、Ant Design Pro Components、Radix UI、shadcn、lucide-react、motion |
| 样式 | Tailwind CSS 4（CSS-first，无 `tailwind.config.js`）、`@tailwindcss/postcss` |
| 存储 | localforage（IndexedDB） |
| 网络 | axios |
| 编辑器 | `@uiw/react-codemirror`、`streamdown` |
| 国际化 | i18next、react-i18next（zh-CN / en-US） |
| 工具 | nanoid、dayjs、fflate、file-saver、copy-to-clipboard |
| 格式化 | Prettier |

包管理器为 bun（仓库同时保留 `bun.lock` 与 `package-lock.json`）。项目未接入 ESLint 和测试框架，`web` 下无测试文件。

脚本：`dev`（端口 3000）、`build`、`start`（预览）、`typecheck`、`format`、`format:check`。

`vite.config.ts` 除常规配置外做了三件事：注入 `@` 路径别名、把根目录 `VERSION` 与 `CHANGELOG.md` 编译进 `__APP_VERSION__` / `__APP_RELEASES__`、通过自定义插件把 `public/plugins/*.js` 暴露为 `/plugins/index.json` 供本地插件发现。

### 画布核心

画布不使用 React Flow 之类的图编辑库，而是自研实现：`components/canvas/infinite-canvas.tsx` 用 CSS `transform` 处理平移缩放，节点由 `components/canvas/canvas-node.tsx` 渲染，连线在 `canvas-connections.tsx`。

内置节点类型定义在 `types/canvas.ts` 的 `CanvasNodeType`，由 `components/canvas/nodes/builtin-nodes.tsx` 注册进 `lib/canvas/node-registry.ts`：

| 类型 | 用途 |
| --- | --- |
| `text` | 文本 / 提示词 |
| `image` | 图片生成与展示，默认锁定原始比例 |
| `video` | 视频生成与展示 |
| `audio` | 音频生成与展示 |
| `config` | 生成参数配置 |
| `group` | 分组容器 |

节点类型是开放字符串，插件节点使用 `<pluginId>:<name>` 形式。`lib/canvas/` 下还有节点工厂、几何计算、尺寸策略、生成辅助、导出、事件总线和资源引用等工具。

### 服务层

`services/api/` 负责外部请求，其余 `services/` 负责本地存储与同步：

| 文件 | 说明 |
| --- | --- |
| `api/image.ts` | 图片生成 / 编辑，兼容 OpenAI、Gemini、Ark 格式 |
| `api/video.ts` | 视频生成与轮询 |
| `api/audio.ts` | 音频生成 |
| `api/model-plugin.ts` | 执行用户自定义的模型调用脚本 |
| `api/prompts.ts`、`api/prompt-source-*.ts` | 提示词来源聚合、预置源与抓取 |
| `api/canvas-agent.ts` | 本地 Agent 的 HTTP 接口 |
| `image-storage.ts`、`file-storage.ts` | 图片 / 媒体 Blob 存取 |
| `webdav-sync.ts`、`app-sync.ts` | WebDAV 协议与业务域同步 |
| `config-file.ts` | 配置导入导出 |
| `local-storage-usage.ts` | 本地存储占用统计 |

AI 渠道配置（`baseUrl`、`apiKey`、`apiFormat`）保存在 `useConfigStore`，请求由浏览器直连，项目本身不代理任何流量。

### 本地存储

IndexedDB 数据库 `infinite-canvas`：

| storeName | 内容 |
| --- | --- |
| `app_state` | 画布、素材、插件等 Zustand 持久化数据 |
| `image_files` | 图片 Blob |
| `media_files` | 视频 / 音频 Blob |
| `image_generation_logs`、`video_generation_logs` | 工作台生成记录 |
| `prompt_cache` | 提示词来源缓存 |

另有数据库 `infinite-canvas-plugins`，按 `pluginId` 分 store 提供插件私有存储。localStorage 只放配置类小数据，如 AI 配置、提示词来源、主题、语言、Agent 地址与令牌、面板宽度。

跨设备同步需自行配置 WebDAV，同步域包括 `canvas`、`assets`、`image-workbench`、`video-workbench`。

### 插件系统

插件以 ES Module 形式运行在主页面，不使用 iframe 隔离：

1. `lib/canvas/plugin-loader.ts` 拉取脚本文本，转成 Blob URL 后动态 `import`。
2. `lib/canvas/plugin-runtime.ts` 通过 `window.InfiniteCanvasRuntime` 注入宿主 React、CSS 注入函数和事件总线，避免插件自带 React 造成双实例。
3. `lib/canvas/node-registry.ts` 注册插件贡献的节点定义，`plugin-node-context.ts` 构造每个节点的上下文。
4. `pages/canvas/hooks/use-plugin-host.tsx` 向插件开放 AI 生成与画布操作能力。

插件来源有三种：远程 URL 安装（缓存源码以便离线）、`web/public/plugins/` 本地发现（默认关闭）、`VITE_DEV_PLUGINS` 开发直挂。官方插件清单地址在 `constant/env.ts` 的 `PLUGIN_REGISTRY_URL`，默认走 jsDelivr 上的 `plugins-dist` 分支。

需要注意插件与模型调用脚本都在主线程执行，具备完整页面权限，安装第三方脚本前需自行确认来源。

### 主题

`lib/app-theme.ts` 提供 Ant Design 的 token 配置，`lib/canvas-theme.ts` 定义画布浅色 / 深色主题，`components/layout/app-providers.tsx` 根据 `useThemeStore` 切换 `documentElement` 的 `dark` class。按 `AGENTS.md` 约定，画布相关 UI 必须走主题 token，不允许硬编码颜色。

## canvas-agent/：本地 Agent

发布为 npm 包 `@basketikun/canvas-agent`，可直接 `npx -y @basketikun/canvas-agent` 启动。

### 技术栈

ESM + TypeScript 5.8，要求 Node 18 以上。依赖 `@modelcontextprotocol/sdk` 提供 MCP 能力、`express` 5 提供 HTTP、`@openai/codex`（固定版本）作为内置 Codex、`zod` 校验入参、`winston` 日志、`gray-matter` 与 `yaml` 解析 Skill。测试用 Node 内置 `node:test` 配合 `tsx` 运行。

### 目录职责

```text
canvas-agent/src/
├── index.ts              CLI 入口，区分 HTTP 模式与 mcp stdio 模式
├── config.ts             配置路径、端口、令牌、工作区
├── server/http.ts        Express 路由、SSE、鉴权与 CORS
├── server/mcp.ts         stdio MCP Server，转发到 HTTP 接口
├── canvas/session.ts     SSE 客户端管理、工具 RPC、会话状态
├── canvas/schemas.ts     MCP 工具名、入参 schema 与描述
├── canvas/operations.ts  高层工具展开为 canvas_apply_ops
├── agent/codex*.ts       Codex 进程、协议、历史与事件补充存储
├── agent/claude.ts       Claude Code CLI 适配
├── agent/message-metadata.ts  消息元数据落盘
├── skills/store.ts       工作区 Skill 增删改查
└── utils/                日志、日期、取值辅助
```

### 运行方式

默认模式启动 HTTP 服务，只监听 `127.0.0.1`，默认端口 `17371`。浏览器通过 `GET /events` 建立 SSE 长连接，Agent 需要读写画布时下发 `tool_call` 事件，浏览器执行后回 `POST /canvas/result`，单次调用超时 30 秒。

传入 `mcp` 参数时不监听端口，改为 stdio MCP Server，把工具调用转发到 HTTP 服务的 `/api/tools`。Codex 侧由 `agent/codex-client.ts` 拉起内置 `codex app-server --stdio`，并自动注入名为 `infinite-canvas` 的 MCP server。

MCP 工具共 35 个，覆盖站点导航、画布读写（节点、连线、视口、选区）、各类生成流程编排、生成状态查询、图片与视频工作台、提示词检索和素材管理。完整清单见 `canvas/schemas.ts`。

### 协议与存储版本

浏览器与 Agent 之间的协议版本 `AGENT_PROTOCOL_VERSION` 定义在 `canvas/session.ts`，通过 `/health`、`/config` 和 SSE 首帧 `hello` 暴露，与 npm 包版本相互独立。

消息元数据存储版本 `STORAGE_VERSION` 定义在 `agent/message-metadata.ts`，读到未知版本或缺失清单时直接报错拒绝覆盖，写入走临时文件原子替换。消息按 `threadId`、`turnId`、`itemId` 三级归属，历史快照成为权威后不再重复合并实时事件。

落盘位置统一在 `~/.infinite-canvas/`：连接配置、Codex 工作区与 Skill、消息元数据、Codex 补充事件历史、调试日志。

### 安全

服务仅监听回环地址，启动时生成随机连接令牌，除 `/health` 和 `/config` 外所有接口都要求携带令牌。首次带令牌成功请求的 Origin 会被记录进白名单，之后其他来源一律拒绝，需要更换时清空配置中的 `origins`。调试日志会对令牌、API Key 和 data URL 做脱敏。

## plugins/：插件

### plugins/canvas/

画布节点插件与 SDK，所有包都是 `private`，不发 npm。

- `sdk/`：`@infinite-canvas/plugin-sdk`，导出类型定义、自动 JSX 运行时、转发到宿主 React 的 hooks，以及基于 esbuild 的 `buildPlugin`。
- `template/`：新插件起步模板。
- `markdown/`、`svg/`、`html/`、`panorama/`、`sticky-note/`：官方插件。
- `registry/`：CI 批量构建脚本，产物强制推送到孤儿分支 `plugins-dist`，再经 jsDelivr 分发。

开发流程是复制模板、改 `id` 与节点 `type`、`npm run dev` 监听构建并同步到 `web/public/plugins/`，或把产物托管到任意地址后在画布内按 URL 安装。

### plugins/infinite-canvas/

Codex app 插件，只有插件描述文件，没有 `package.json`。`.mcp.json` 声明 MCP server 走 `npx -y @basketikun/canvas-agent mcp`，`skills/` 下提供操作画布与打开画布两个 Skill。通过 `codex plugin marketplace add` 加上仓库根目录后安装。

## docs/：文档站

Next.js 16 + Fumadocs 16，MDX 内容放在 `docs/content/docs/`，分为 `overview`、`canvas`、`development`、`progress`、`business`、`support` 六个板块，每篇文档都有英文版和 `.zh-CN.mdx` 中文版，导航顺序由各目录的 `meta.json` / `meta.zh-CN.json` 控制。

`docs/index.md` 与 `docs/index.zh-CN.md` 是给 AI 使用的文档索引，不属于内容目录。

## 部署与 CI

前端 `Dockerfile` 用 bun 构建后交给 nginx 托管，容器暴露 3000 端口，nginx 对 SPA 做 `try_files` 回退并对 `/config.js` 关闭缓存。`vercel.json` 与 `render.yaml` 分别对应两个托管平台。

`.github/workflows/` 下四个流程都由 `v*` tag 推送或手动触发：发布 GitHub Pages、构建多架构前端镜像、构建文档镜像、构建并发布官方插件到 `plugins-dist`。

## 开发约定

- 修改代码前先读 `AGENTS.md`，其中包含目录归属、组件拆分、主题使用和文档更新的硬性约束。
- 项目尚未上线，本地存储结构可直接按新设计调整，不写旧数据兼容。
- 全局状态放 `stores/`，跨页面 UI 副作用放 `hooks/`，画布工具函数放 `lib/canvas/`，外部请求放 `services/api/`。
- 重大改动完成后在 `CHANGELOG.md` 的 `Unreleased` 追加记录，待办与待测事项分别维护在 `progress/todo` 与 `progress/pending-test`。
