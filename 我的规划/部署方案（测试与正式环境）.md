# 优刻服务器部署实施手册

## 第一阶段：部署测试站

1. 确认 Fork 仓库地址、测试提交和服务器计划端口；不直接 clone 上游部署账号后端。
2. 将代码放入测试目录，复制 `deploy/env.test.example` 为 `deploy/env.test`。填写随机数据库密码、测试密钥与管理员；`APP_BASE_URL=https://sim-art.youc.online`、`SITE_ENV=test`、`COOKIE_SECURE=true`、`API_BASE_URL` 留空，数据库连接仍为 `db:3306/infinite_canvas_test`。
3. 保留模板已有超时与大小边界，不临时增加经验值。替换所有密钥占位值；测试与正式分别生成密钥。测试不接真实支付，免费赠送保持模板的关闭状态，测试 seed 可用于初始化示例数据。
4. 补齐 Docker 构建上下文对实际 env 与本手册的排除后，执行未来部署命令：

```bash
cd /opt/infinite-canvas-test
./deploy.sh test build
./deploy.sh test up -d
./deploy.sh test ps
```

5. 宿主机 `/etc/nginx/sites-available/` 新增测试站，启用到 `sites-enabled/`。借鉴已有站点的路径透传、请求头和 SSE 配置，目标为 `http://127.0.0.1:3100`，不剥掉 `/api`。按当前站点已有代理边界复核 AI 流式和媒体上传，两层代理都要满足应用需求。
6. 为 `sim-art.youc.online` 配置匹配证书，不复用仅包含 `art.youc.online` 的证书，不重启已有应用来申请证书。应用 Nginx 变更前检查配置，再平滑 reload。
7. 按通用部署手册验收登录、媒体、AI、SSE、重启恢复和隧道。测试模板当前关闭审核；启用 fake 只能联调审核流程，不能视为真实审核通过。

这时本地可以只跑前端，共用服务器测试 API；完整本地 Go 模式见第三阶段。

## 第二阶段：数据库工具与本地前端

在电脑打开测试数据库隧道，保持终端运行：

```bash
ssh -N -L 127.0.0.1:13306:127.0.0.1:13306 root@104.250.130.10
```

DBeaver 在电脑安装，新建 MySQL 连接：主机 `127.0.0.1`、端口 `13306`、数据库 `infinite_canvas_test`、用户名 `canvas_test`，密码取实际测试库配置。使用上述终端隧道时，DBeaver 不再启用内置 SSH。该固定隧道也供本地 Go 使用，SSH 密码不是 MySQL 密码。

仅查看数据库也可使用 DBeaver 内置 SSH：SSH 主机 `104.250.130.10`、端口 `22`、用户使用获授权账号；MySQL 仍填服务器侧 `127.0.0.1:13306`。DBeaver 动态本地转发端口不作为 Go 的固定连接入口。Community 版可查表、执行 SQL、看 ER 结构图；SELECT 结果的分析图表属于付费版本。

只改前端时，不运行本地 Go，另开 API 隧道：

```bash
ssh -N -L 127.0.0.1:8080:127.0.0.1:3100 root@104.250.130.10
```

再在代码目录的 `web/` 运行 `bun run dev`，打开 `http://localhost:3000`。保持 API base 为空，当前 Vite 代理会从本机 `8080` 进入服务器测试 API。本机 `8080` 不能同时被本地 Go 占用。验收刷新 Cookie、媒体加载和 SSE；该路径不依赖测试域名证书，但不能替代服务器 HTTPS 入口验收。

## 第三阶段：本地前后端共用测试数据（前置开发待完成）

目标路径为本地 Vite → 本地 Go → SSH → 同一个 `infinite_canvas_test`。服务器测试 Go 同时为测试站服务，两端共用测试私有 S3 桶。

按顺序补齐：

1. 确定测试 S3 兼容提供方和桶，将服务器测试媒体与本地 Go 配到同一存储。端点与预签名 URL 需两端浏览器可达，桶保持私有并配置 CORS。已有 local 媒体如需保留，在暂停写入后复制到正确对象路径并验证；不能只切驱动后继续使用空桶。
2. 为 Go 增加启动维护与后台任务执行开关。服务器测试 Go 是默认唯一执行者，本地 Go 关闭自动迁移、seed、管理员初始化、启动请求收敛、订单扫描、视频轮询、隔离清理与注销处理。当前没有这些开关，不凭空填写变量名。
3. 准备本地仓库根目录 `.env.local`：数据库改为 `127.0.0.1:13306/infinite_canvas_test`，共享测试 JWT/凭据主密钥和 S3 配置，本地页面地址使用 `http://localhost:3000`，HTTP Cookie 使用 `COOKIE_SECURE=false`。正确引用连接串与密码，在启动前加载到进程环境；Go 不会自行读取 `.env`。
4. 关闭前端专用的本机 `8080` SSH 转发，让本地 Go 监听 `8080`；保留数据库 `13306` 隧道，本地 Vite 仍同源代理 `/api` 到 Go。
5. 修改测试库结构由指定执行者操作；本地与服务器代码都需兼容该结构。站点设置当前按进程缓存，另一端或 DBeaver 修改后需重启相关进程或采用落实后的刷新方式。
6. 验收两端创建/读取画布与媒体、生成任务只由一处轮询、账本一致和正式数据隔离。调试资金相关数据使用业务接口，不只改余额或订单单表。

完整共享模式不作为正式多实例架构；进程内限流、并发与设置缓存仍有各自边界。若暂未完成这些前置条件，只使用第二阶段的本地前端联调。

## 第四阶段：正式部署与域名切换

1. 完成测试验收，经用户明确同意后合入 `main` 并打版本 tag；本任务不执行合并或部署。
2. 在正式目录检出该 tag，填写独立 `deploy/env.prod`：正式 MySQL、密钥、管理员、SMTP 与媒体；`APP_BASE_URL=https://art.youc.online`、端口 `3200`、`SITE_ENV=production`、`COOKIE_SECURE=true`、`SEED_TEST_DATA=false`。正式库不映射宿主机 MySQL 端口。
3. 正式镜像标签包含验收版本，记录提交、镜像 ID 和有效配置。保留旧版本镜像；脚本不会自动保存旧镜像或校验 ref。
4. 完成真实审核所需推理服务和 API ffmpeg；实际启用微信支付时补私钥只读挂载；SMTP 验收真实验证/重置邮件，STARTTLS 分支若使用需先修复。
5. 准备数据库、媒体、env/密钥和版本记录的联合备份，并在测试环境演练恢复；频率、保留策略与异地位置由实施时确认。普通媒体周期清理和磁盘监控仍需落地。
6. 构建并启动正式服务，确认容器健康、反代、静态资源和业务链路。new-api 已收敛到 `api.youc.online` 专用，`art.youc.online` 当前与测试同源（`3100`），正式上线后将 `/etc/nginx/sites-available/art.youc.online` 的目标由 `3100` 切为 `3200`，配置确认后 reload，保留 `api` 与 `ai` 的既有服务。

## 更新与恢复

测试目录更新目标提交 → 构建测试镜像 → 启动 → 验收；正式目录仅升级到已验收 tag。不要在两套环境同用一个 checkout 后直接 `git pull` 构建。

每次正式升级前备份并保留旧镜像。AutoMigrate 没有自动回滚；切回旧镜像只退代码，不一定恢复数据库结构。需要数据恢复时，先停止所有相关写入者，再恢复对应数据库、媒体和密钥。正式上线后按已规划的版本化 migration 管理结构变更。

本手册只记录规划与检查证据。服务器部署、共享媒体、Go 开关、正式切换和恢复演练完成后，分别更新 TODO / pending-test，不提前标记为已上线或已验收。
