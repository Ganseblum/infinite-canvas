# 第五期执行计划：内容审核与人工复核

本文档是[账号后端总规划](账号后端总规划.md)第五期的中文执行计划。前置条件是[第四期](第四期-AI请求后端转发与点数计量.md)已交付并通过验收，平台模型请求、报价预扣、结果落盘与生成记录已经由服务端统一掌控。

## 范围界定

### 本期要做

- 接入开源内容审核方案：图片用 NSFWJS（本地推理），文本用 Detoxify（本地推理），封装文本与图片审核适配层。
- 全部生成请求在预扣前审核提示词与参考图，在产物进入正式媒体存储前审核生成结果。
- 用户上传的参考图与素材在 `PUT /api/media` 入盘时经过媒体审核。
- 新增审核记录、短期隔离区、人工复核、统计、告警和管理员补偿流程。
- 明确审核不可用时的失败策略、数据最小化、保留期和用户提示。
- 完成对外开放注册前的技术验收，并把算法备案、大模型服务备案、账号注销入口可用和服务条款确认作为独立上线门禁。

### 本期不做

- 不触碰服务端不可达的场景：用户在本地设备或第三方工具里使用导出内容的行为不经过本站。
- 不手写图片、视频或文本分类算法；统一使用成熟开源模型（NSFWJS、Detoxify），但部署、阈值与策略由平台自行维护。
- 不接付费内容安全 SaaS（阿里云内容安全等）。开源方案满足当前阶段的审核需求；若后续监管要求必须使用有资质的服务商，再单独立项更换 provider 实现——适配层接口不变，替换只涉及一个 provider 文件。
- 不把「站内生成与上传全链路审核」扩大成「用户的全部内容均经审核」，对外文案只覆盖服务端实际可达的链路。
- 不实现用户自助申诉系统。v1 由管理员人工复核和客服补偿，后续再根据量级规划用户侧工单。
- 不因审核误判自动退款。人工补偿进入 `granted` 桶，不复用生成失败退款链路。

## 阶段目标与完成定义

| 目标 | 完成定义 | 主要证据 |
| --- | --- | --- |
| 输入审核前置 | 平台提示词和参考图被拒时不预扣点数、不调用上游 | 调用计数、流水与审核记录 |
| 产物审核闭环 | 平台产物先进入隔离区，审核通过才进入正式存储；拒绝产物不可被用户访问 | 隔离区与正式桶检查 |
| 上传审核有效 | 用户上传的参考图与素材在落盘前审核，拒绝后不占用正式配额 | 上传集成测试与用量对账 |
| 结论可追溯 | 每次审核记录阶段、对象哈希、标签、服务商请求 id、策略版本和最终结论 | 管理后台与数据库检查 |
| 人工复核可执行 | 管理员可查看仍在隔离期的内容、改判、释放或删除，并按规则补偿 | 完整复核演练 |
| 隐私最小化 | 普通审核记录不保存原始提示词和媒体；隔离原件加密、限权、短期自动删除 | 存储和权限检查 |
| 故障策略明确 | `MODERATION_FAIL_MODE` 必填，超时、限流、服务异常均告警并按配置处理 | 故障注入测试 |
| 公开运营门禁明确 | 技术审核、备案、条款、告警和人工值守全部确认后才能开放注册 | 上线检查表签字记录 |

## 审核覆盖边界

| 链路 | 提示词 | 参考图 | 产物 | 说明 |
| --- | --- | --- | --- | --- |
| 平台模型生成 | 服务端预审 | 服务端预审 | 服务端后审 | 全链路审核 |
| 用户上传（参考图、素材） | — | 服务端预审 | — | 入盘前审核 |

前端输入提示只能减少无效请求，不能作为合规依据。服务端可达链路的审核不得因前端已经检查而省略；对外文案必须准确描述覆盖边界。

## 实施任务与顺序

| 顺序 | 任务 | 主要文件 | 具体改动 | 任务完成检查 |
| --- | --- | --- | --- | --- |
| 1 | 固定审核契约 | `server/internal/moderation/`、配置和模型 | 定义阶段、结论、标签、策略版本、服务商响应摘要和失败分类 | fake provider 契约测试通过 |
| 2 | 建记录与隔离区 | moderation model/service、storage quarantine driver | 建审核记录；原件进入私有隔离前缀，加密并设置删除时间 | 普通媒体接口无法读取隔离对象 |
| 3 | 接平台输入预审 | AI handler/service、quote/预扣流程 | 提示词与参考图审核放在报价确认后、实际预扣前 | 拒绝输入无上游调用、无消费流水 |
| 4 | 接平台产物后审 | provider result、media/generation service | 上游产物下载到隔离区，审核通过后转正式存储，拒绝则删除或等待复核 | 用户无法访问拒绝产物，点数不自动退 |
| 5 | 接媒体上传审核 | media handler、storage service | 流式写隔离区、审核、通过后提交；拒绝和失败不污染正式对象及用量 | 违规媒体上传被拒 |
| 6 | 建人工复核 | admin moderation API、`web/src/pages/admin/moderation/` | 列表、详情、改判、释放、删除、补偿入口和审计 | 管理员完整处理一次误判 |
| 7 | 建统计与告警 | moderation metrics、日志、管理统计 | 命中率、失败率、延迟、标签分布、积压和隔离区用量 | 阈值触发真实告警 |
| 8 | 故障与隐私验收 | 集成测试、运维检查表、条款 | 注入超时、模型加载失败、OOM，检查 fail mode；核对保留期和公开文案 | 全部上线门禁有证据 |

先用 fake provider 跑通状态机和失败分支，再接真实 NSFWJS 与 Detoxify 推理。不能一开始就依赖真实模型调试所有业务逻辑，否则模型加载与推理抖动会掩盖本地状态错误。

## 开源审核方案选型

审核服务商从付费 SaaS（阿里云内容安全）改为开源自托管方案，理由：零审核调用费用、数据不出服务器、无第三方账号依赖。代价是精度低于商用服务、需要自己维护模型更新与 GPU/CPU 推理资源、且没有内容安全资质背书——公开运营前必须完成算法备案等合规门禁，若监管要求使用有资质服务商，只需替换 provider 实现。

| 能力 | 选型 | 说明 |
| --- | --- | --- |
| 图片审核（参考图、产物、上传） | [NSFWJS](https://github.com/infinitered/nsfwjs) | TF.js 模型，五分类（neutral / drawings / hentai / porn / sexy），输出各分类概率；Node 端跑 `@tensorflow/tfjs-node`，模型文件随服务部署；CPU 推理单张约 100–300ms，量级上来后再考虑 GPU |
| 文本审核（提示词） | [Detoxify](https://github.com/unitaryai/detoxify) | RoBERTa 系毒性分类（toxic / severe_toxic / obscene / threat / insult / identity_hate），Python 服务以 HTTP 暴露，Go 后端调用；CPU 推理单条约 50–200ms |
| 视频审核 | 抽帧 + NSFWJS | v1 不做端到端视频模型：按固定间隔（如每秒 1 帧）抽帧，逐帧或抽样过 NSFWJS，任一帧超阈值即拒绝 |
| 阈值与标签映射 | 平台策略层 | NSFWJS 的五分类与 Detoxify 的标签统一映射为平台风险标签（如 `adult`、`toxic`、`violence`），阈值写入 `MODERATION_POLICY_VERSION` 标注的策略配置，可调整并使缓存失效 |

部署形态：审核模块随 Go 后端同机部署为两个 sidecar 容器——NSFWJS 在 Node 侧进程（TF.js 原生绑定），Detoxify 在 Python 侧进程，二者只监听 compose 内网、不经 nginx 暴露公网；Go 通过本地 HTTP 调用并纳入 `MODERATION_TIMEOUT` 超时控制，推理进程崩溃时按 fail mode 处理并告警，与外部服务故障同等对待。CPU 推理即可起步（图片约 100–300ms/张、文本约 50–200ms/条），量级上来后再给 NSFWJS 进程加 GPU。

检测时机为**同步内联**，不是异步队列，共四个触发点：提示词与参考图在 `/api/ai/*` 报价确认后、预扣点数前审核（被拒返回 422，不扣点、不调上游）；图片产物在上游返回后先写隔离区、审核通过才转正式存储（用户多感知约 200ms）；视频产物在隔离区内用 ffmpeg 按 `MODERATION_VIDEO_SAMPLE_FPS` 抽帧、逐帧过 NSFWJS、任一帧超阈值整条拒绝，任务状态机增加 `moderating` 态（`queued → running → moderating → success/failed`），轮询接口原样返回该状态；上传媒体在 `PUT /api/media` 流式写隔离区后审核，通过才提交正式对象并计配额。

## 数据模型

### `moderation_records`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | char(36) | 主键 |
| `user_id` | char(36) | 用户 id |
| `generation_id` | char(36) | 关联生成记录，可空 |
| `media_file_id` | char(36) | 关联媒体记录，可空 |
| `stage` | varchar | `prompt` / `reference` / `artifact` / `upload` |
| `content_type` | varchar | `text` / `image` / `video` / `audio` |
| `content_hash` | varchar(64) | 内容 SHA-256，用于追踪和去重，不可反推原文 |
| `provider` | varchar | 审核服务商 |
| `provider_request_id` | varchar | 服务商请求 id |
| `policy_version` | varchar | 平台审核策略版本 |
| `provider_result` | json | 服务商结论摘要和命中标签，不保存原始内容 |
| `decision` | varchar | `pending` / `passed` / `rejected` / `error` |
| `risk_labels` | json | 规范化风险标签数组 |
| `quarantine_key` | varchar | 隔离对象 key，可空，不通过普通媒体接口暴露 |
| `quarantine_expires_at` | datetime(3) | 隔离原件自动删除时间，可空 |
| `review_status` | varchar | `not_required` / `pending` / `approved` / `rejected` |
| `reviewed_by` | char(36) | 复核管理员，可空 |
| `review_note` | varchar | 复核说明 |
| `reviewed_at` | datetime(3) | 复核时间，可空 |
| `created_at` / `updated_at` | datetime(3) | UTC 时间 |

索引至少包含 `(user_id, created_at)`、`(decision, created_at)`、`(review_status, created_at)`、`content_hash` 和 `provider_request_id`。审核记录只追加服务商事实，人工改判通过复核字段表达，不覆盖原始服务商结论。

### 业务表状态

第二期已经在 `generations` 与 `media_files` 建好 `moderation_status`，本期启用：

- `skipped`：审核链路上线前产生，或按明确策略不在覆盖范围内。
- `pending`：正在审核或等待人工复核，用户不可读取产物。
- `passed`：自动或人工审核通过，可正常读取。
- `rejected`：自动或人工拒绝，不可进入正式媒体存储。
- `error`：审核服务失败且当前策略不允许放行。

状态更新与媒体从隔离区转入正式存储必须保持一致。数据库显示 `passed` 但文件仍在隔离区，或正式文件已可访问但状态还是 `pending`，都属于阻断级故障。

## 审核流程

### 平台输入

顺序固定为：参数和报价凭证校验 → 文本审核 → 参考图审核 → 存储与并发检查 → 免费次数占用或点数预扣 → 上游请求。

输入被拒时返回 422 `CONTENT_REJECTED`，带用户可理解的风险类别，不返回服务商原始详情；不占免费次数、不写消费流水、不调用上游。审核记录保存文本哈希、标签和服务商摘要，不保存原始提示词。

相同用户、相同内容哈希、相同策略版本在短时间内可复用通过结论以降低延迟，但拒绝结论是否缓存必须保守处理。策略版本变化后旧缓存立即失效。

### 平台产物

上游返回的媒体先写入私有隔离区，不能直接写正式 `storageKey`。审核通过后再提交到正式对象存储并写 `media_files`；审核拒绝时生成记录标记 `rejected`，隔离对象默认保留 24 小时供人工复核，期满自动物理删除。

产物拒绝不自动退点，因为上游成本已经发生。页面在生成前明确提示这条规则；误判由管理员复核后释放产物，或通过第三期的管理员点数接口向 `granted` 桶补偿。

### 用户上传

用户上传的参考图与素材（例如本地图片传进画布或素材库）在 `PUT /api/media/{storageKey}` 审核。上传先流式写隔离区并计算哈希，审核通过后才提交正式对象和增加 `usage_records.storage_bytes`；拒绝或失败时不增加正式用量。

同一 `storageKey` 重试必须幂等，不能遗留多个隔离对象。上传请求中断时清理未完成临时对象；清理失败进入隔离区垃圾回收任务，不进入用户正式空间。

### 审核服务不可用

`MODERATION_FAIL_MODE` 必须显式配置：

- `reject`：返回 503 `MODERATION_UNAVAILABLE`，不预扣、不调用上游、不提交媒体。公开运营默认使用这一模式。
- `allow`：仅允许私有化部署方明确选择；记录 `decision = error` 与 `moderation_status = skipped` 后继续，并持续告警。

未配置时服务启动失败。不能在代码里静默默认放行，也不能把超时当成“未命中”。平台输入审核、平台产物审核和媒体上传审核使用同一 fail mode，避免同一次内容在不同入口得到相反处理。

## 接口与错误码

用户侧不新增审核查询接口，生成和上传接口直接返回最终可执行结论。本期新增错误码：

| HTTP | code | 说明 |
| --- | --- | --- |
| 422 | `CONTENT_REJECTED` | 输入、参考图、产物或上传内容未通过审核 |
| 503 | `MODERATION_UNAVAILABLE` | 审核服务不可用且 fail mode 为 `reject` |
| 409 | `MODERATION_ALREADY_REVIEWED` | 对同一记录重复提交互相冲突的人工结论 |

管理接口全部要求 `role = admin`：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/moderation/records` | 按阶段、结论、标签、复核状态、用户和时间筛选 |
| GET | `/api/admin/moderation/records/{id}` | 审核详情；隔离原件仍有效时返回短期预览地址 |
| PATCH | `/api/admin/moderation/records/{id}` | 提交人工通过或拒绝，必须带说明和当前 revision |
| POST | `/api/admin/moderation/records/{id}/compensate` | 向 `granted` 桶补偿，必须带金额和说明 |
| GET | `/api/admin/moderation/stats` | 命中率、失败率、延迟、标签分布、积压和误判改判率 |

详情接口生成的预览 URL 只允许管理员、有效期不超过 5 分钟，响应禁止缓存。复核 PATCH 使用 revision 防止两个管理员互相覆盖；冲突返回 409，由前端刷新最新结果。

补偿接口不能自己修改余额，必须调用第三期的 credit service，并写 `bucket = granted`、`type = grant`、`ref_type = moderation` 的流水。自动审核通过后不得再补偿；同一审核记录的补偿使用唯一业务 id 保证幂等。

## 前端改造

- 生成页、画布生成节点和上传入口统一处理 `CONTENT_REJECTED` 与 `MODERATION_UNAVAILABLE`：422 展示拒绝原因和「修改内容后重试」，保留用户输入；503 按「审核服务暂时不可用，请稍后重试」提示并禁用生成按钮，**不做自动重试**——fail mode 是 `reject` 时重试只会反复撞墙。
- 两个错误码的文案按第一期机制登记进 `apiErrors.*`，与生成页、上传入口共用同一份。
- 报价区域明确提示“输入被拒不扣点；产物生成后审核不通过仍会扣点”。
- 平台生成记录展示 `pending`、`passed`、`rejected`，拒绝记录不渲染裂图或失效预览。
- 新增 `web/src/pages/admin/moderation/`，页面私有组件放同目录 `components/`，不放到共享 admin 目录。
- 复核详情显示服务商标签、摘要、策略版本、时间线和短期隔离预览；不在前端持久化隔离 URL。
- 人工补偿必须二次确认，明确显示进入赠送桶、不改变付费身份。
- 页面文案保持中文；业务组件不单独覆盖弹层和主题颜色。

| `MODERATION_IMAGE_THRESHOLD` | 图片违规判定阈值（如 porn/hentai 概率 ≥ 0.6 拒绝），按策略配置 |
| `MODERATION_TEXT_THRESHOLD` | 文本毒性判定阈值，按策略配置 |
| `MODERATION_VIDEO_SAMPLE_FPS` | 视频抽帧采样频率，默认每秒 1 帧 |
| `MODERATION_FAIL_MODE` | `reject` 或 `allow`，无默认值 |
| `MODERATION_TIMEOUT` | 单次审核超时（含推理进程响应） |
| `MODERATION_POLICY_VERSION` | 当前策略版本，变更后使缓存失效 |
| `MODERATION_QUARANTINE_TTL` | 隔离原件保留时间，默认 24 小时 |
| `MODERATION_CACHE_TTL` | 同用户、同哈希、同策略通过结论缓存时间 |

至少监控审核请求量、通过率、拒绝率、错误率、P95 延迟、各风险标签分布、人工复核积压、自动拒绝后改判率、隔离对象数量和字节数。错误率或延迟超过阈值必须告警；改判率持续升高说明策略过严，应调整策略而不是让客服长期补偿。

## 阶段检查与纠偏

| 偏离信号 | 说明 | 立即纠偏 |
| --- | --- | --- |
| 只在前端拦关键词 | 可被绕过，不能作为合规能力 | 停止公开验收，把审核放回服务端写路径 |
| 输入审核发生在预扣之后 | 被拒输入会无故占点 | 调整到预扣前，并补“无流水、无上游调用”断言 |
| 平台产物先进入正式存储再审核 | 审核窗口内违规内容可访问 | 改为隔离区先审后提交，关闭正式读权限直至通过 |
| 审核记录长期保存原始提示词或媒体 | 超出追溯需要，扩大隐私风险 | 记录改为哈希和摘要；原件只放短期隔离区 |
| `allow` 被当作默认值 | 审核故障会静默放行 | 配置改为必填，公开运营切回 `reject` 并复验 |
| 绕过 `/api/ai/*` 的生成请求被放行 | 存在未经审核的生成链路 | 拒绝该入口；生成只允许走服务端转发这一条路径 |
| 产物拒绝自动退款 | 形成违规内容免费算力通道 | 恢复“不自动退点”，误判走复核与赠送补偿 |
| 管理员可通过普通媒体 URL 查看隔离内容 | 隔离权限失效 | 使用独立短期预览 URL、禁止缓存并记录访问 |
| 宣传「用户的全部内容均经审核」 | 用户导出内容与设备本地内容不经过本站 | 立即修正文案、条款和客服口径，只承诺站内生成与上传链路 |

出现审核绕过或隔离对象公开可读时，立即关闭平台模型和媒体上传，保留登录、数据读取和导出。修复后从入口、对象存储权限、CDN 缓存和历史访问 URL 四层复验；只修前端按钮不算完成。

## 阶段门禁

- 自动化：fake provider 覆盖通过、拒绝、超时、429、5xx、重复回调、缓存和并发复核。
- 真实服务：NSFWJS 与 Detoxify 分别跑通图片（含视频抽帧）和文本样例，记录推理服务响应摘要。
- 财务：输入拒绝无预扣；产物拒绝保留消费；误判补偿只进 `granted`，逐桶对账仍成立。
- 存储：拒绝内容不进入正式桶、不增加正式用量；隔离原件按 TTL 删除且不可通过普通媒体接口读取。
- 权限：非管理员无法读取审核详情或隔离预览；管理员操作有身份、时间和说明。
- 故障：`reject` 与 `allow` 两种模式都做故障注入；未配置 fail mode 时启动失败。
- 文案：产品页、服务条款和隐私说明准确描述覆盖边界、扣费规则、数据保留和人工复核。
- 合规：算法备案、大模型服务备案和法务确认独立完成；技术测试通过不能替代这些事项。
- 发布：上述门禁全部通过并确认人工复核值守后，才允许打开公开注册和平台模型入口。

## 验收清单

平台输入：

- 违规提示词返回 `CONTENT_REJECTED`，点数和免费次数不变，上游调用次数为零。
- 违规参考图在预扣前被拒，正式媒体和生成记录中没有新产物。
- 正常提示词审核通过后按 Phase 4 的报价预扣并生成，审核额外延迟可观测。
- 同一内容在同策略版本下命中通过缓存；策略版本变化后重新请求服务商。

平台产物：

- 正常图片和视频先进入隔离区，审核通过后才获得正式 `storageKey`。
- 违规产物不可由用户读取，生成记录为 `rejected`，点数不自动退还。
- 隔离预览只能由管理员短期访问，普通用户和其他管理员会话复制 URL 后均不能长期复用。
- 隔离 TTL 到期后原件物理删除，审核记录的哈希和摘要仍保留。

用户上传：

- 违规的参考图与素材在上传时被拒，不进入正式桶、不增加存储计数。
- 正常媒体审核通过后照常显示；同一 `storageKey` 重试不产生重复正式或隔离对象。
- 上传中断留下的临时对象能被清理，不能进入用户媒体列表。

人工复核：

- 管理员能按标签、阶段、结论和时间筛选记录并查看仍有效的隔离预览。
- 两名管理员同时复核同一记录，后一人收到 revision 冲突，不能覆盖前一结论。
- 将误判改为通过后，隔离期内的产物可安全释放；已过期时明确提示原件已删除，不能伪造恢复成功。
- 补偿写入 `granted` 桶并留下审核记录 id，同一记录重复补偿不重复到账。

故障与上线：

- 审核服务超时、429 和 5xx 在 `reject` 模式下均不预扣、不请求生成上游、不提交上传媒体，并触发告警。
- `allow` 模式只在明确配置后生效，记录为 `error/skipped` 并持续告警。
- 未配置 `MODERATION_FAIL_MODE` 时服务拒绝启动。
- 管理统计能看到命中率、错误率、P95 延迟、标签分布、复核积压与改判率。
- 对外说明只承诺站内生成与上传链路已被审核，不扩大到用户导出内容与设备本地内容。
