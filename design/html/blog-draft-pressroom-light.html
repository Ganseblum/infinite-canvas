把画布搬进浏览器之后

2026-08-30 · 4,288 字 · 约 12 分钟 · 封面 AI 生成 · 保存为草稿时还没想好结尾

引子：过去一年，我的创作动线是「生成—下载—再上传—再导出」，文件在五个工具之间来回搬。直到我把整条动线塞进一张无限画布，事情才开始变得像创作本身。

一、为什么是画布

文件夹是给归档用的，不是给思考用的。当你同时面对 30 张候选图、4 段配乐和一版还在改的文案，空间关系比目录树更接近大脑的工作方式——把相关的摆近一点，把废案拖到远处，本身就是一次整理。

无限画布解决了这个问题，但市面上的画布工具都不管「生产」：它们擅长便签和连线，不擅长生成、版本和导出。于是只好自己动手，顺带把工作流重新设计了一遍[1]。动手之前，先立三条边界：

  • 画布数据全部存浏览器本地，不上云
  • 生成节点必须能挂回原始提示词与参数
  • 多人协作——先不做，一个人用就够
「工具链的每一次跳转，都是一次上下文丢失。画布的价值不在于无限大，而在于不用离开。」—— 写在重构第一周

TIP — 顺手记

Markdown 管线里这叫 Callout（> [!TIP]）。写作时少用「注意」多用「为什么」，读者才会停下来。

二、三个关键取舍

缩略图先行

画布上几百个节点同时渲染原图是不现实的。导出 768px WebP 缩略图、按缩放级别回退原图，是整条链路里回报最高的一个决定。

canvas/thumbnail.tsREAD
// 按缩放级别决定加载哪一档
const src = scale < 0.4 ? thumb768 : original;

状态留在本地

画布数据全部存浏览器本地，不上云。代价是换设备要手动迁移，收益是深夜赶稿时不必考虑任何人的服务器。

WARNING — 别学我

本地存储没有版本历史。重构存储结构前先备份，遇到未知版本或损坏清单要拒绝迁移，这个亏我吃过两次。

四、一年下来的账

把感受换成数字，账本其实挺诚实——素材找回时间从分钟级降到秒级，导出环节彻底消失：

指标画布前画布后
找一张三个月前的图约 4 分钟（翻文件夹）约 8 秒（框选缩略图）
导出一张分享图3 步 · 跨 2 个工具1 步 · 画布内框选
废弃方案占比61%34%（废案留得下）

三、还没解决的

协作是没有的，同步也是没有的。这篇文章保存为草稿的时候，结尾还没想好——但发布按钮已经排好了版，等它想好的那天再补。

ABOUT — 关于本站

HANG'S NOTEBOOK.

主站是放映厅，这里是放映厅后台的排字房——作品怎么被做出来，就在这里怎么被写下来。

我是航，做图像，也做动态；排得了一页 PPT，也写得了长文。白天在无限画布里生产作品，晚上把过程里的坑、轮子和取舍记在这里——权当给下一次的自己留排字稿。

这里写三类东西：怎么做的（AI 工作流、独立开发）、怎么排的（模板、配色与排版）、怎么想的（创作方法与碎念）。月更，一期一到四篇，宁可慢，不烂尾。

文章全部以 Markdown 起稿，在后台排好版、点了「发布」才会见读者。AI 参与生成的封面与配图一律带角标，正文一个字一个字自己写的。
